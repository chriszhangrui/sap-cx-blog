今天看到一条消息值得聊聊。Allytics 那边出了一篇 SAP Sapphire 2026 的复盘文章，标题就两个词：Headlines 和 Undercurrent。头条和潜流。这个分法很妙，正好对上我这两天的感受——SAP 在台上喊的是一回事，焊在底层的是另一回事。

写下来给你看看。

## 头条是什么

先说台面上喊的。这次 Sapphire 的 C 位是 Business AI Platform，SAP 把它定位成"智能控制中枢"，下面挂一个 Autonomous Suite，再下面是 224 个预置 agent 和 51 个 Joule Assistant。Joule 升级成了 Joule Work，从问答助手变成工作流入口，Joule Studio 2.0 让客户和合作伙伴自己造 agent。A2A 协议 Q4 GA，意思是不同厂商的 agent 之间能互相喊话。

五个所谓的"自治领域"——Finance、Spend、Supply Chain、HCM、CX——CX 只是其中一个。说白了就是，SAP 这次画的是一张大图，CX 是图上的一块拼图，不是主角。

如果你只看头条，会觉得这是一场"agent 接管业务"的发布会。但 Allytics 那篇文章真正有意思的地方在后半段。

## 但潜流不一样

潜流是什么？是那些不太上头条、但藏在产品架构里的细节。

最让我注意的是 NVIDIA OpenShell——一个跑在 SAP 这边的 agent runtime，专门做 agent 行为的隔离、审计和回溯。还有 AI Agent Hub，管 agent 的全生命周期：上线、下线、版本、权限、SLA、成本归集，全在这里。Knowledge Graph 和 Company Memory 不是炫技，是给 agent 一个有边界的"工作记忆"，避免它跑出去乱抓数据。

把这几个东西摆在一起看，画风就变了。

> SAP 一边告诉客户"agent 自己跑业务"，一边花大力气告诉客户"我们能管住它"。Headlines 卖的是自治，Undercurrent 卖的是控制。后者才是给企业掏钱的那个理由。

这事儿在企业软件里其实不新鲜。十年前云转型也是这套路——台上讲 elasticity，签合同的时候客户问的全是 SLA、备份、合规、审计。这次只是把主角换成了 agent。

## CX 项目里这件事怎么落

回到我们手里的活。中国企业出海做 CX，尤其是跨境电商和跨国企业的中国业务部分，今年绕不开一个时间点：欧盟 AI Act 八月起对高风险 AI 系统的合规义务开始落地，往后还有 2027、2028 几道关。客服 agent、营销决策 agent、信用评估 agent，这几类基本都会被划到"高风险"或者临近高风险的范围。

这时候 AI Agent Hub 的"上户口"机制就有意义了。它不是新功能，是合规的承载体——agent 的版本、训练数据来源、审批人、运行日志、变更记录，监管来查的时候能拿出来。OpenShell 那一层负责 runtime 隔离，Knowledge Graph 控制数据边界，三层叠在一起就是企业级 AI 治理的最低配。

所以给客户讲方案的时候，不要只讲"我们有 224 个 agent"，那是 demo 话术。真正能进采购流程的话术是："这 224 个 agent 的版本、数据、行为，我们都能拉出审计报告。"

## 中国企业出海要看什么

竞品对比这块也得换个角度。Salesforce Agentforce 在 agent 数量、用户体验、生态丰富度上目前是领先的，这个不用绕。但 SAP 的差异化不在数量，在治理纵深——Agent Hub + OpenShell + Knowledge Graph 这套组合，是给那种"被监管盯着、出问题要写说明的"客户准备的。汽车、医药、金融、跨国制造，这几类客户的采购决策权重里，可审计性 > 体验丰富度。

还有一个细节值得提一下：A2A 协议 Q4 GA。这意味着 SAP 的 agent 和 Salesforce、ServiceNow、微软的 agent 理论上能互通。对中国出海企业来说，这是个机会——你不需要把所有系统都换成 SAP，只需要在 SAP 这边管好"自家 agent"，跨厂商协作有协议托底。

> 我的判断是，SAP 这次真正卖的不是 200 多个 agent，是这套 agent 的"上户口"机制。出海企业选 SAP CX 的理由，不该是"功能比 Salesforce 多"，而是"出问题的时候能交代清楚"。前者是市场部话术，后者是 CIO 签字的理由。
