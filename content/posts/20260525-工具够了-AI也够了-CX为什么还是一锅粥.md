想象一个跨境品牌的市场总监 Lin，周一早晨 9 点打开电脑。她要给欧洲市场推一个新品系列：先在 SAP Engagement Cloud 里看上周邮件数据，再切到 Sales Cloud 查关键客户的对接进度，又跳进 Commerce Cloud 后台看 SKU 是否上架，再回邮件回复服务团队的一个客户投诉——那个客户上周下了大单这周却抱怨发货慢。

五个系统，五张账户，五份"半张脸"的客户视图。她每个动作都是合理的，每个工具都是先进的，可整件事让人很累。更要命的是：上周她已经发出去的促销邮件，跟服务团队那边正在道歉的事，是同一个客户。

这不是 Lin 一个人的问题。这是 CX 这件事在 2026 年最大的尴尬：工具越来越多，AI 越加越快，体验却没有按比例变好。**5 月 21 日 CX Today 那篇 SAP 首席营销官 Jessica Keehn 的访谈，把这件事挑明了——CX 现在的瓶颈不是智能不够，是没人编排。**

![](https://www.cxtoday.com/wp-content/uploads/2026/05/Why-Does-Customer-Experience-Have-an-Operating-Model-Problem-1.png)

> "品牌不应该追求把 Agent 加得更多，而是要让对的那些 Agent 围绕同一份事实工作，让团队动作更快、摩擦更少。"——SAP CMO Jessica Keehn

## 协调缺口，藏在用户看不见的地方

Keehn 那段话其实捅破了一个事：今天的 CX 失败，往往不是发生在客户面前，而是发生在客户感知不到的后端。

企业平台越加越多，工具越买越贵，但流程之间的"缝"也越多。一个营销团队上了自动化平台，一个客服团队上了 AI 客服，一个电商团队上了推荐引擎——单看每条线都没问题。问题是，没有人能回答"这个动作是哪个 Agent 在做""它的数据从哪里来""它做错了谁负责"。

Keehn 在访谈里给了个具体的清单：企业需要一份 Agent 的清单、一套访问控制、一份能看见每个 Agent 在干什么的可视化、还要确保它们都在安全地运行。听起来像是 IT 治理，但背后说的是经营问题——当你的客户旅程是被一群你管不住的程序碎片拼起来的，你给客户的就是一个不靠谱的体验。

客户那一头看到的是什么？是被反复要求"再说一遍订单号"，是不同渠道给出矛盾的答复，是问题转了三个团队还没解决。**客户感知到的不是哪个 AI 不智能，而是这家公司在他们身后乱成一团。**

## "工具足够了，但模型还没换"

这句话不是 Keehn 原话，是读完她那段访谈后的感受。她原话是这么说的："太多组织里，营销、销售、电商、服务、供应链、财务还在各自跑各自的系统，每个系统对客户和业务都只有一半的视角。"

这是个老问题。但 AI 时代它变得不一样了。

以前你可以说"我们工具不够，所以体验断点多"。现在工具够了，AI 也够便宜了，问题暴露在另一面：经营模型本身没改。各部门各自买 Agent、各自接数据、各自定义"客户优先"的口径，最后你的客户站在前面，看到的不是一家公司，是 N 个互相不认账的子公司。

访谈里 Keehn 给了一个特别实在的例子：一个营销人不应该需要知道——哪个 Agent 能找到关键人群、哪个能查库存、哪个能生成内容、哪个能调整投放、哪个能触发下一步动作。这个事应该让系统去搞定。

这就是 SAP 在 Sapphire 2026 主推"自治企业"叙事的真正逻辑。**不是加更多 Agent，是把 Agent 接到一个共享的客户事实层上去，再加上治理。**这也是为什么 SAP 这一年密集收购 Reltio、Dremio、Prior Labs，为什么 Business Data Cloud 被推到台前——它要做的不是再造一个 CRM，是给所有那些 CRM、CDP、电商、ERP 一个共同的"对客户的理解"。

## 从全渠道一致，到"持续的上下文"

Keehn 在访谈最后抛出一个新概念——CX 进入"持续上下文（Continuous Context）"时代。

老一代的全渠道（Omnichannel）解决的是"我在哪个渠道找你都能找到"。但 2026 的客户期待已经升级了：他们要的不只是渠道一致，而是"你每次跟我说话，都接着上次的故事讲"。客户不再容忍"上一次邮件聊到第 5 步，下一次客服电话回到第 1 步"。

这件事说起来简单，落地很难。它要求三件事都到位：共享的数据结构、实时的运营感知、以及可以让多团队多系统都按同一份理解去行动的治理模型。中间任何一环断了，"持续上下文"就掉成"持续骚扰"。

这也是为什么 Keehn 在访谈里反复强调一句话：复杂应该发生在幕后，让用户那边感觉简单。今天大部分企业是反着做的——内部表面上看着井井有条，每个团队 KPI 都达标了，但客户端体验是一锅粥。

## 这条信号给中国出海品牌的提示

回到开头那个 Lin。如果 SAP 这套"自治企业 + 持续上下文"的故事真的落地了，她的周一早晨会变成什么样？

不会再是五个系统五张脸。她会看到一个统一的工作面——上周哪封邮件触达了哪个客户、哪个客户在 Commerce 上加购又流失、哪个客户的售后单还在转、这些信息在她打开电脑那一刻就已经被串好。她不需要去问"哪个 Agent 干这个"，她只需要做决策：是给那位投诉的大客户先发个补救券，还是让销售直接打电话。

中国出海品牌、跨境电商、跨国制造的全球总部，这几年共同的难题就是这条：在多个市场、多个语言、多个仓配体系下，怎么做到客户体验是连贯的。多数团队的解法是"再加一个工具"——再上一个营销云、再加一个客服系统、再换一个 CDP。

Keehn 这次访谈的真正价值，是把行业的注意力拉回到一个不性感的话题上：**CX 不缺工具，缺的是统一的运营模型。**中国品牌做海外市场扩张时，与其问"这个产品有多少 AI 能力"，不如问"它跟我现有的销售、服务、电商、供应链怎么编排在一起"。

SAP 把宝押在这条线上，赢面有多大，要看接下来一年那些数据产品、Agent Hub、Joule Studio 落地到客户现场的速度。但这个判断本身——"问题不在 Agent 多不多，在编排到不到位"——是这一波 AI 热里少见的清醒话。

至少，对周一早晨九点的 Lin 来说，是这样。
