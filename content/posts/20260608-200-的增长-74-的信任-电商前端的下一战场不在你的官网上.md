Salesforce Connections 2026 上周在芝加哥开完，最值得 SAP Commerce Cloud 客户认真看的一句话来自 Salesforce 行业洞察总监 Caila Schwartz：消费者在 AI 搜索里"先问一句再去别处"的比例，同比涨了 200%，74% 的购物者会信任 AI 给出的推荐。

这两个数字摆在一起，意思就一个——你的电商官网正在丢掉它二十年来最重要的入口位置。

Schwartz 和产品经理 Adam Levine 这场题为《Win the Agentic Web Through GEO and Intent-Based Discovery》的分享，把过去半年大家含糊讨论的"AI 搜索冲击"具体化成了三件事：内容要为 AI 优化、要给 AI 提供足够的上下文和权威信号、品牌要在自有渠道之外的整个互联网上"露脸"。这是他们对 GEO（Generative Engine Optimization）下的定义。

在传统 SEO 时代，品牌的官网是终点。在 GEO 的世界里，它退回到了一个数据源。

## 自有 Agent 和外部 LLM，分工已经清楚了

一个让我比较意外的判断是：Salesforce 不再坚持让消费者回到品牌自有 Agent 上完成所有事。Schwartz 给的分工很直白：

- 品牌自有 Agent 处理订单查询、客服、退换货、会员体系——所有跟这次交易和这位客户的长期关系深度绑定的事；
- 外部 LLM（ChatGPT、Perplexity、Gemini）处理礼物推荐、语义搜索、跨品牌比价、技术建议——所有"先问问看"性质的事。

这跟过去几年 Commerce 圈讨论的"私域为王"是一个相反的判断。消费者并没有回流到品牌自营触点，他们在 LLM 里完成了从需求识别到候选名单的整个上半场，然后才决定去哪家官网下单。

对 SAP Commerce Cloud 上做出海生意的客户来说，这个分工意味着两件事：自有站点上的 Agent 不用做成万能助手，把订单和会员体验做扎实就够；但站点外的"被发现"这件事，过去基本没人在做。

## Crawl 还是 Feed？现在两个都得做

Levine 在分享里讲清了一个让所有电商人头疼的问题：AI 搜索引擎到底是怎么读你的产品的？答案是两条路并行——爬取（Crawl）和喂数据（Feed）。

Google Merchant Center 已经成熟多年，每天接收上千个商家的产品数据流。OpenAI 即将开始接收商品 Feed 用于 ChatGPT 的购物推荐。但 Anthropic 的 Claude 暂时只走爬取，没有 Feed 通道。同时所有走 Feed 的 LLM，在回答某些问题时还是会回头爬你的官网。

Levine 给的建议没什么花活：现阶段两条都做，别赌。

但 Feed 本身正在变。过去做 Google Shopping 的电商团队都熟悉那套基础字段——名称、描述、尺寸、颜色、材质。现在 LLM 想要的是一类新字段，Levine 称为"对话式属性"（conversational attributes），描述的是消费者会在对话里提到的具体场景、意图和建议。

举个例子，传统 Feed 里你写"男士皮夹克 L 码 黑色"。对话式属性里你需要补的是"适合北方冬季短途骑行""可以搭配商务休闲""礼物预算 2000 以内"这种东西。这是 LLM 把用户的口语化需求和产品撮合在一起所需要的桥接信息。

对 SAP Commerce Cloud 客户来说，PIM 里这部分语义层的数据基本都是缺的。Emarsys 那边收集的客户行为数据可以反过来给 PIM 喂这类标签，CDP 里的客户分群也能告诉你哪些"对话式"维度在不同市场里更值钱——但前提是产品团队、营销团队和数据团队这三方愿意坐下来把这件事拉通。

## 关于 Crawl，反而没那么神秘

Levine 在台上反驳了最近半年甚嚣尘上的一个说法——给 LLM 单独做一套站点结构。他的判断是：到目前为止没有数据支持这种做法的额外收益，所谓的"LLM markup"基本是个传说。

他给出的优化清单，跟 SEO 的老路子重合度极高：

- 不要拦爬虫，确认 robots 设置正常；
- 不要用阻塞渲染的 JS——HTML 工作得很好；
- 内容质量是单一最重要的杠杆。LLM 在它的索引库里挑能引用的片段时，"有真人视角的、第一手的、能解决具体问题的内容"会被优先于"模板化的、客套话堆起来的"内容选中。

FAQ 页面被 Levine 单独点了名。他建议商家把客户真正会问的问题用第一人称方式答出来，既放在站点上也写进 Feed。当消费者在 ChatGPT 里问类似问题时，LLM 引用的就是这种和原始问题表述最接近的回答。

> "高质量、权威、真实、人写给人看的内容，是你能做的单一最重要的事。"——Adam Levine，Salesforce Commerce Cloud

这句话听起来像废话。但放在大量品牌过去三年都在用 AI 批量生产 SEO 文案的背景下，它其实是个矛盾的提醒——AI 在选择引用谁的时候，恰恰会绕开 AI 写的那批内容。

## 对国内出海企业的几点提醒

Salesforce 这场分享的视角是美国本土零售品牌。但 SAP Commerce Cloud 在中国的客户，真正面临的是一个更复杂的版本——你的目标客户在 ChatGPT、Perplexity、Gemini 上搜索，但你大部分内容资产在中文官网、抖音、小红书上。这个错配比美国品牌严重得多。

几条具体建议：

**英文内容资产的"密度"是第一优先级**。出海品牌过去常见的做法是把中文产品页机翻成英文挂上去，这种内容在 LLM 的引用排序里几乎没有任何竞争力。在 LLM 的索引里，一篇有视角、有数据、有案例的英文长文，价值高于五十个机翻产品描述。

**Reddit 和老牌内容站点是被低估的渠道**。后续另一场关于 LLM 引用来源的演讲里有个很关键的数据——Perplexity 一半以上的引用来自 Reddit，OpenAI 在维基百科上的引用占其全部引用的 50%。这意味着出海品牌如果想被 ChatGPT 推荐，光做自己官网的内容是不够的，得在英文社区生态里有真实的存在感。

**Commerce Cloud 的 PIM + Emarsys 的行为数据 + CDP 的分群**，这三件事如果能联动起来，输出的 Feed 字段质量会比单纯做 PIM 的品牌高一个层级。Salesforce 演讲里提到的"对话式属性"，本质上是一个跨系统协作问题，不是某个单系统的功能。

**FAQ 是低成本高回报的切入点**。中国品牌的英文站 FAQ 普遍写得很差，要么没有，要么从中文直译。把客服日志里真实出现的英文问题整理出来，用第一人称重写一遍——这件事不需要预算，本周就能开始做。

GEO 这个词大概率明年就会被新的缩写取代。但它指向的事情——品牌不再控制消费者从哪里开始搜索——是结构性的。Salesforce Connections 上花一小时讲清楚的是动作清单，不是远景。Crawl 和 Feed 同时做、把内容真的写好、在站点之外露脸，这三件事现在做和明年做，差距会随着那个 200% 继续往上叠。
