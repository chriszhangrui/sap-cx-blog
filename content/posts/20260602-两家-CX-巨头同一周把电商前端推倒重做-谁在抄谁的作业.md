5 月 26 日，Salesforce 把它的 B2C Commerce 前端推倒重做了，叫 **Storefront Next**。同一周稍早，SAP 在 Sapphire 上把 Vercel 拉进来，作为 SAP Commerce Cloud 与自定义体验层的前端选项。两家全球 CX 巨头，几乎踩着同一个时间点，对各自的电商前端动了大手术。

这事有点像两家头部车厂同一周发布新一代电动平台。表面是产品发布，里子是路线选择。**看新闻稿都说自己 AI-first、易用、企业级，但真正值得读的是它们怎么定义"前端"这件事。** 路径分歧才是这两条新闻最有信息量的地方。

## Salesforce 的答案：30 分钟开店，自己包圆

Karly Cyr（Salesforce B2C Commerce 高级产品营销经理）在官方博客里把客户的痛点拆成了两类：一类是被"轻量方案"困住的——比如 Shopify 起家的品牌，活动期间性能崩、第三方 App 拼成一团浆糊；另一类是被"企业平台"压住的——技术债太重，迁移到 Agentic 工作流像开盲盒。

Storefront Next 的卖点是把这两端各取所长。商家点几下就能拉起一个店铺模板、托管环境、API 连接和 GitHub 仓库——**用时不超过 30 分钟**。开发者拿到这套代码，再用配套的 *Agentic B2C Developer Toolkit*，可以把 Claude Code、Agentforce Vibes、GitHub Copilot 接进去做 vibe coding。Astound Digital 报的数据是实施周期和成本下降 30%。Forward 报的更夸张——之前他们的 FastForward 加速器在 PWA Kit 上花了 6 个开发者 6 个月，迁到 Storefront Next 上换成 6 个 AI agent 跑了一周多。

还有一个动作不太显眼但其实更重要：**Commerce Apps 框架**。Adyen、Avalara、Bazaarvoice、Contentstack、Stripe、Mirakl 这些 ISV 第一批进驻，被打包成"装好即用"的应用。商家在 Business Manager 里点一下就能装上，不用写胶水代码。本质上 Salesforce 在做的是 **把整个前端 + 集成层都装进自家应用商店**，让客户少操心生态拼装。

## SAP 的答案：地基自己留，前端外包给生态

SAP 在 Sapphire 2026 上的动作是另一种姿态。Commerce Cloud 这边搞了个 ERP-Native Edition（"runs with"，不是"runs beside"），同时官方把 Vercel 抬到了一个明确位置——做 SAP Commerce 和自定义体验层的前端选择。换句话说，SAP 没自己重写一套店铺模板生成器，**它把前端这一段直接交给了行业里最锋利的那把刀**。

这就像有的车厂自己造车机系统，有的车厂直接接 CarPlay。SAP 选了后一条。背后逻辑也不复杂——Composable Storefront（Spartacus 演进过来的那条线）已经走了几年开放路线，原生支持 SSR、PWA、Headless API。再造一套封闭模板，反而是开倒车。

SAP 真正下力气的地方在底座。**Joule 把电商体验串成一条 Agent 链——Merchandising、Shopping、Order Lifecycle 三个 Joule Agent 接在一起**，前端不管你用 Vercel、用 Composable Storefront、用客户自己的 Next.js，对接的是统一的 Commerce 后台和 Agent 层。SAP 押的是"AI 在底座、前端开放"，前端长什么样不重要，重要的是 AI 能调度商品、订单、客户数据。

## 两条路对应两类客户假设

Storefront Next 是给那种"我没有强大开发团队、我希望厂商把 80% 的事都做好"的零售客户准备的。30 分钟开店、Commerce Apps 装一装、AI 工具包接进去——这套故事讲给中型 DTC 品牌、Direct to Consumer 起家的品牌、想从 Shopify Plus 升级又怕进 enterprise 大坑的品牌，听起来非常顺耳。

SAP + Vercel 的组合呢，画像是另一种：**大型多品牌零售集团、跨国制造企业、有 ERP 订单库存深度集成需求的 B2B 或 B2B2C**。这些客户不缺前端开发能力，他们缺的是"后台几十个系统怎么不打架"。Vercel 在前端，SAP Commerce 在中后台，BDC 做数据底座，Joule 做编排——这是给那些已经在 SAP 生态里的客户继续往上长的。

所以两家不是在抢同一群客户。Salesforce 想往中端下沉、用易用性扩大盘子；SAP 守住自己的高端基本盘，把开放的部分让出去给生态做。**这反而是两家产品哲学第一次在同一个赛道上互不交叉地展开**。

## 中国出海品牌该怎么看

具体到中国出海的电商决策者。如果团队不大、目标海外市场以欧美 DTC 为主、技术栈以 SaaS 为主，Storefront Next 的故事会更动人——尤其是它内置 ISV 应用（Adyen、Stripe、Bazaarvoice 这些是出海跨境标配）。

如果你已经是大型跨境集团、海外有多品牌多市场矩阵、ERP 已经在 SAP 上、订单和库存要跨国调度，那 Vercel + SAP Commerce 这套组合更现实——尤其是 SAP Commerce Cloud ERP Edition 释放的信号，"电商焊回 ERP"对这种盘子来说不是负担而是省成本。

还有一个角度容易被忽略：**Composable Storefront 的迁移期还有一年多**。SAP 把 Vercel 抬上来，明确告诉现有 Hybris 客户——你不一定要去 Salesforce 那边换山头，留在 SAP 体系内换前端是可行的，而且换的是市面上最主流的工具。这个信号对 SI 合作伙伴和 SAP 现有客户都很关键。

## 真正值得追问的一句话

两家厂商同周对前端动手，不是巧合。Agentic Commerce 时代的前端，承担的不只是渲染商品，还要承接 AI Agent 的语义、上下文和决策。**前端不是页面，是 Agent 的脸。**

Salesforce 选的是"我把脸也给你画好"，SAP 选的是"脸你自己画，但脑子接我的"。哪条路赢，取决于客户更信哪一句承诺。半年到一年内会出落地数据，到时候再回头看这周，可能会发现这是两家真正分道扬镳的开始。
