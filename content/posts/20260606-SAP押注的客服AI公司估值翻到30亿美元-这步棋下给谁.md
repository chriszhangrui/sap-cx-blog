> 一家德国 AI 公司，把自己卖进了 Service Cloud

30 亿美元估值，350 百万美元 D 轮，七个月之前公司刚刚跨过独角兽这条线。一家叫 Parloa 的柏林公司，5 月 29 日公布了这串数字，领投人是 SAP，参投名单里挤着微软。这家做了八年的客服 AI 公司，从 C 轮到 D 轮，只用了七个月。

如果只看融资新闻，这就是一条"AI 又爆了"的常规播报。真正值得拆开看的，是 SAP 这一笔投资背后的产品决策——SAP 没有自己做客服 AI Agent，而是把 Parloa 的引擎直接装进了 Service Cloud。

## SAP 不做的那部分

先把数据列清楚。Parloa 一年 ARR 过 5000 万美元，净收入留存率 150%——也就是说，老客户每年自己在续单基础上多花 50% 的钱。客户名单里有 Allianz、Booking.com，还有美国医疗系统巨头 HealthEquity，最近又接通了 Epic 的 HIPAA 合规通道。这一组数据放在 SaaS 行业里都属于头部水平。

SAP 这一笔投资的特别之处不在"金额大"，而在"动作罕见"。SAP 历史上极少做这种规模的少数股权投资。回看过去两年，SAP 拿真金白银押注的几家公司，几乎都是为了某一块产品空白下的赌注——Reltio 是为了主数据，Dremio 是为了 Lakehouse，Prior Labs 是为了基础模型。这次轮到 Parloa，就说明 SAP 自己心里清楚：客服 AI Agent 这一块，现在还做不了第一名。

![Parloa 关键数据](https://mma.prnewswire.com/media/2977146/parloaxsap_1.jpg)

这件事之前讲过——Sapphire Orlando 上 SAP 公布了 Service Cloud 内置 Parloa Agent 的事。当时被埋在 200 个 Agent 的清单里没怎么被注意。但今天回头看，那个公告是有分量的：SAP 在 Service Cloud 里上的客服 AI Agent，模型不是自己训的，引擎不是自己写的，调度逻辑不是自己造的——是直接接 Parloa 的 Agent Management Platform。

## 外包大脑这件事

这就引出第一个问题：客服 AI 这条线，凭什么 SAP 自己不做？

客服领域的 AI Agent，本质上是个"语音+对话+流程编排"的组合活。光会聊天不够，还得能调 Five9 这类呼叫中心、能接 ServiceNow 工单、能识别 1500 种欧洲口音、能在凌晨三点的电话里准确听懂客户在说"我账单不对"。这种能力的积累，需要真实跑过几亿次电话才能磨出来。Parloa 在 BPO 巨头 Teleperformance、Concentrix、Foundever 那里跑了多年，攒下的语料和场景，SAP 短期内造不出来。

这就像一家做汽车的厂商，自己不造发动机，而是绑定一家发动机供应商。Sapphire 上 SAP 把这步棋讲成"开放生态"，但本质是"先把这道难题外包出去"。

第二个问题更现实——SAP 投的钱，给 Parloa 带来什么？

明面上是 D 轮领投。暗面里是 SAP 把 Parloa 的客服平台部署成了内部 IT 支持工具，自己 11 万员工的 IT helpdesk 都跑在 Parloa 上。这是连产品验证都不用做的"超级 reference customer"。

> "客户旅程已经成为企业内部最具基础性的 agentic AI 落地面。"
> —— Malte Kosub，Parloa CEO

## 这事对中国出海企业意味着什么

先讲一个判断：在中国出海客户的 SAP CX 项目里，Service Cloud V2 的渗透率本来就不高，国内客户讲到"客服 AI"通常意识里浮现的是阿里小蜜、华为云客服这类工具。Parloa 这个名字，对绝大多数中国 IT 决策者完全是空白。

但出海公司不一样。一家从义乌走向北美的家居跨境品牌，它的客服系统可能是 Zendesk，可能是 Genesys，也可能直接挂在 Five9。这些系统现在都开始接 Parloa——一旦你的全球客户接通过电话进来，背后回答的可能就是 Parloa 的 AI Agent。

这意味着两件事：

- **选 Service Cloud V2 的中国出海客户**，要重新审视 Parloa 在自己客服 Agent 路线图里的位置。SAP 给的不只是 Service Cloud，还包括接到背后的 Parloa 引擎——这是过去没有的能力。
- **已经有 SAP CX 部署的在华跨国总部**，2026 下半年至 2027 年的 Service Cloud 升级路径里，会大概率出现 Parloa Agent 的预集成模块。这一块的实施工作量、与现有 IVR 系统的衔接、和呼叫中心运营商（TP、Concentrix）的合同条款——这些是新的项目讨论变量。

第三件事是给售前和 SI 合作伙伴的提醒。Parloa 之前不是大多数 SAP 生态合作伙伴熟悉的名字。但接下来 12 个月，Parloa 会出现在 RFP 模板、Service Cloud 报价单和客户的"AI Agent 架构图"里。提早把这家公司的产品边界、定价模式、与 Joule 的协作关系搞清楚，比之后再补课要好。

## 一个被忽略的细节

Parloa 的另一个投资人是微软，不是 OpenAI 也不是 Google。Parloa 的底层云架构跑在 Azure 上。OpenAI 也合作——平台用了 GPT 5.4。这意味着，当一家中国出海公司把自己的全球客服系统升级到带 Parloa 能力的 Service Cloud V2 时，这套链路实际上是"SAP 主控 + Microsoft Azure 承载 + OpenAI 模型推理 + Parloa 调度"。四方协同，没有一方是单独可以决策的。

这是一个值得提前画在合规架构图上的事实。涉及客户语音数据的跨境传输、模型日志保存、第三方调用审计——欧盟 AI Act 8 月开始执行的那些条款，每一条都会落到这条链路上。

## 行动建议

如果你正在评估 Service Cloud V2，或者已经在 Service Cloud V2 上跑了一段时间，下面这三件事可以现在就做：

- **第一**，让团队跟 SAP 客户经理确认 Parloa 在 Service Cloud 的集成路线图——是 OEM 嵌入、独立购买，还是绑定销售。这个商业模式会直接影响后期的 TCO 估算。
- **第二**，把 Parloa 加进 vendor scoring matrix。即使现在不买，也要在内部对它有基础认识。它不是 Salesforce Einstein，也不是 Genesys，定位介于 CCaaS 平台增强和 Agent 编排层之间。
- **第三**，关注 6 月初 Parloa 即将发布的 Consumer Patience Index 报告。一份关于"消费者对 AI 客服的耐心阈值"的实证研究，对今年下半年要做客服 AI 落地的公司来说，是一份免费的市场基线数据。

SAP 选择把 Service Cloud 的 AI 大脑外包给 Parloa，赌的是 Parloa 能跑得比自己快。这个判断对不对，还要再过两年才能看清楚。但对正在或者即将选 SAP CX 的中国出海公司来说，这件事现在就该进入决策视野——你的下一个客服 AI 升级方案里，可能已经有一个叫 Parloa 的德国公司，悄悄站在中间。
