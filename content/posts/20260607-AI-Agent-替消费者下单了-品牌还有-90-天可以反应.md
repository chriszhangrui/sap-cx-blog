今天看到一条消息值得聊聊。

Avenue Z 一个叫 Thomas Stern 的人去 Azoma 那场 Agentic Commerce 大会，回来写了篇行动指南，标题就是「品牌该在 90 天里做什么」。我把它读完之后第一反应是——这事其实不新，但放在 SAP CX 客户面前，问题正在变得很尖锐。

说白了就是：AI Agent 已经开始替消费者比价、下单、续订。Bain 那份报告甚至预测，未来 agent-to-agent 的链路可能完全绕开传统电商网站。Google 五月底刚把 Universal Cart 推上线，把购物车从浏览器里挪了出去；AWS 把亚马逊内部的 shopping agent 打包成了 Agentic Shopping Assistant on AWS——这两件事都是过去三周里发生的。

那么品牌侧的人到底在焦虑什么？Thomas 那篇文章给了 6 个落地点。我想顺着这 6 条往下扒一扒，每一条对照看一下 SAP CX 客户手里现成的产品，到底卡在哪一步。

## 第一件事：先把产品和品牌数据梳一遍

Thomas 把这条放在最前面，原因很朴素——AI 系统不信任脏数据。商品标题、属性、描述、包装明细、分类法、宣称内容——只要在零售商和品牌官网之间不一致，AI 就不会用你的版本。

这件事乍看像是 PIM 的活，但放到出海品牌身上要复杂得多。一个常见的场景是：

- 同一款 SKU 在 Amazon、独立站、Tmall Global、TikTok Shop 上有四套不同的标题
- 中文母版翻成五种语言的过程中，某个核心宣称被译错
- 包装规格在 ERP 里写的是克，在 Shopify 上写的是盎司

SAP 这边其实有 Inriver——上个月 SAP 给它盖了「Built with BTP」的认证章。这步棋的潜台词就是：SAP 不想自己重做 PIM，但要确保 PIM 出来的数据干净地灌进 Commerce Cloud 和 Engagement Cloud。对中国出海品牌来说，PIM 已经从「锦上添花」变成「不接 Agent 就上不了牌桌」。

## 第二件事：从关键词思维换成问题思维

这一条比前面那条难。AI 系统不是在匹配关键词，是在回答消费者一连串的语境化问题——这个产品给谁用、解决什么场景、怎么用、和别的有什么区别。

这意味着 PDP 页面不能再是 SKU 加几张图就完事的电商模板。我接触过的几个出海客户，过去半年都在重做产品详情页，把 FAQ、应用场景、对比内容塞进去，让爬虫能完整解析一个使用故事。Commerce Cloud 这次的 Composable Storefront 升级，加上 Q3 即将 GA 的语义层接入，本质上就是在给这件事铺地基。

> 引用一段 Thomas 的原文判断：「如果你的文案只是在镜像零售商的分类法，对今天的购物行为来说就太薄了。」这句话我建议每个 CX 项目的内容运营至少抄一遍。

## 第三件事：把 brand.com 重新当成业绩资产

这一条挺反直觉。过去几年大家都在说独立站要走 Headless、走 Composable，重心是把流量从独立站匀到 marketplace 上。但当 AI 系统开始用品牌官网当真相之源，独立站的角色就变了——它不再只是转化漏斗的一个入口，更像是给 Agent 看的「公开知识库」。

中国出海品牌做这件事的难度也很特殊：

- 独立站 SEO 内容质量普遍低于欧美同行——大量页面是从中文翻过来的，问答密度不够
- 美区合规、欧盟合规要求的 ingredient/claim 信息没有结构化标注
- 多语言版本之间事实点会跑偏

Commerce Cloud + Inriver + Engagement Cloud 这条链路，理论上能把这件事做完，但 90% 的项目在落地时都死在了内容运营这一环——技术架构没问题，是没人写得出来。

## 第四件事：内容策略不够，得做引用策略

Thomas 这一条戳得比较狠。AI 系统不只看品牌自己说什么，更看 earned media、第三方测评、论坛、榜单怎么说你。他用了一个词——citation strategy，引用策略。

PR、传播、社交、电商、内容五个团队过去是分头跑的。在 Agent 时代他们必须坐到一张桌子上，因为 AI 评判一个品牌可信度的方式，不是看你的官网有多漂亮，而是看 Reddit、Trustpilot、Wirecutter 这些第三方源头怎么交叉验证你。

这件事 SAP 没有现成的产品来覆盖。Engagement Cloud 解决营销自动化，但搞不到第三方语料层。这是 SI 和品牌内容团队真正能创造价值的地方。

## 第五件事：建一个跨职能的小组，现在就建

这条听起来像废话，但 Thomas 现场观察到的是——准备得最好的品牌都在跨电商、品牌、PR、法务、分析、IT/数据、产品/品类七条线建快速实验小组。

我看到的项目里，问题往往出在 IT 这边——SAP CX 项目通常是 IT 主导落地，但 Agent 时代的内容质量、citation 策略、PDP 重写这些事，IT 一个人做不下来。出海品牌总部对接的 CIO/CTO 如果还在按旧节奏推 Commerce Cloud 升级，没把品牌端、内容端、法务端拉进同一个 sprint，那项目交付完之后大概率还是「技术上对，业务上空」。

## 第六件事：度量框架不完美也得开始测

没人能给 agentic commerce 一套完整的度量。但 Thomas 提到几个先动起来的指标——share of voice、AI 可见性、排名变化、内容表现、转化漂移。

这跟 SAP 这边的工具栈倒是能接上。Engagement Cloud Q2 那次更新里，事件总线和数据底座都做了改造，原本就是为了把这种偏向行为信号的数据接进 BDC。问题在于多数客户连基础的 CDP 数据模型都没建好，更别说在上面叠 AI 可见性指标。

## 我的判断是

Thomas 这 6 条本质上是在说同一件事：当 Agent 替消费者下单的时候，品牌的护城河从「广告投放精准度」变成「数据 + 内容 + 第三方背书」三层结构的整体质量。

SAP CX 这套产品组合——Commerce Cloud 做交易层、Engagement Cloud 做触达层、BDC 做数据底座、Inriver 做产品数据——架构是对的。但绝大多数中国出海品牌目前最薄弱的不是工具，是组织——PR 和电商两条线根本不通，PIM 数据归市场还是归运营都说不清。如果 Sapphire 上画的那些 Agent 蓝图要真正落地到出海品牌身上，先得有人把这 6 件事在内部重新组织一遍。

90 天的窗口期不是 Thomas 编出来的——是 Google、AWS、Snowflake 这几家在 5 月底到 6 月初密集推产品的节奏给压出来的。Agent 已经站到收银台前了，品牌这边还在开会决定谁负责接它。
