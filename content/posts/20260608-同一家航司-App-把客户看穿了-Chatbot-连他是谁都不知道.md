一名美国旅客在登机当天发现自己的 TSA PreCheck 认证刚刚过期，登机牌没打上对应标识。航空公司的 App 主动发了告警，告诉他这是个异常并给出处理路径；同一家航司的客服 Chatbot，却像第一次接触一个陌生人，问了二十分钟还在念政策条款。

两个 AI，同一家公司，同一个客户，同一小时，结果完全相反。

**这不是 AI 模型的问题，是它能不能拿到数据的问题。**

这件事来自 Info-Tech Research Group 的分析师 Shashi Bellamkonda 上周发的一篇手记，发生在他自己身上。我把它单独拎出来讲，是因为这道题对正在选型 SAP CX 的中国出海企业，比 Sapphire 上那 200 个 Joule Agent 加起来都更值得琢磨。

**App 那边发生了什么。** 它读了客户过去 14 段飞行记录，识别出 PreCheck 标识异常缺失，在抵达登机口之前就把告警推给了客户，还顺便给出了 TSA 的多种联系方式，并诚实地标注：当日解决并不一定来得及。

**Chatbot 那边发生了什么。** 它没接订单系统，不知道这个客户是谁、订过哪趟航班，更不知道运营 App 已经给同一个人发过一条精准告警。它眼里这是一次新接触、一个陌生提问，于是开始念知识库——TSA 网站链接、PreCheck 通用流程、续期提醒、政策定义。20 分钟过去，三个人工坐席接力 2.5 小时，绕了一大圈，最终给出的答复和自动系统 20 分钟前的结论一模一样：联系 TSA，等。

> 一个客户，一家公司，两个 AI 之间没有任何"对方已经知道了什么"的共识。

**这件事最刺眼的不是体验差，是预期被对齐了一次又被打回原形。** App 已经把"这家航司的 AI 知道我"这个预期植入到客户脑子里，再去找 Chatbot 时，对方完全没接住——这一刻客户感受到的不是"功能有限"，而是"这家公司不在乎"。

那段文字最值得抄下来的一句话是：在客服 AI 前面摆一个大模型，等于给这次互动装上了智能——这个假设是错的。智能在这里只取决于一件事，模型在那一刻能拿到什么数据。

**这恰恰是 SAP CX 选型最该被问、却最常被跳过的一题。** Sales Cloud V2、Service Cloud V2、Commerce Cloud、Engagement Cloud（Emarsys）、Customer Data Platform、Customer Loyalty Management，再加上 OMS 和 BDC——这些产品任何一个都能上 AI Agent，每一个产品页都能列出一长串"AI 能力"。但客户进来不是按产品名分裂的：他在 App 看到一条推送，转手去 Web 客服问问题，再去门店扫个码——他眼里这是同一段旅程。

这就是为什么 SAP 这两年把那么多力气花在 BDC、Customer Data Platform、Knowledge Graph 这种"看不见的底座"上——不是底座本身好卖，是上面的 Agent 没有它就跑成第二个 Chatbot。

**真正卡人的不是技术路径，是组织。** Bellamkonda 在文中写得直白：让客服平台和 App 平台拿同一份数据、对同一个客户结果指标负责，技术上不复杂——共享客户数据层、跨渠道身份解析、上下文随交接传递。难的是这件事意味着两个团队的边界要重新画，预算口径也得改。

中国出海品牌在做 SAP CX 落地时，最容易踩的恰恰是这一步。Commerce Cloud 上一个 SI、Sales Cloud V2 上另一个 SI、Engagement Cloud 又是第三家——三条线都做出来了，三个团队各自有 KPI，但中间那一层"客户数据怎么共享"没人主管。等到三个 AI Agent 同时上线，客户在不同触点拿到三种结果，CIO 才发现真正欠的账在底座。

> 在扩大客服 AI 的覆盖面之前，先回答一个问题：每一个客户触点背后的客户数据层，是不是同一个团队在管。

**那句话用来反问 SAP 的 Autonomous CX 故事也成立。** SAP 在 Sapphire 上摆了一排 Joule Agent，从售前线索打分到售后退货编排都有专属 Agent。但这些 Agent 单独看是合格的，组合起来能不能跑——取决于 Customer Data Platform 有没有把 Sales、Service、Commerce、Engagement Cloud 的客户事件汇成一条线，取决于 Knowledge Graph 有没有把不同业务对象的关系标注清楚，也取决于 BDC 那条 Zero-Copy 链路有没有和你 S/4 里的订单、物流、库存数据接上。

不接，也能跑——跑出来的就是那家航空公司的 Chatbot。客户问 PreCheck，它给你念政策。客户问"我那笔退款到哪了"，它告诉你查询路径在官网哪一栏。

**这件事还有第三层意思。** App 的告警之所以让客户记住了，不是因为它解决了问题——它没解决——而是因为它对客户当下的处境是"知道的"。Bellamkonda 把这点说得很狠：这家公司接下来每一次和这个客户的接触，都会被这条预期照着量。任何一个比 App 知道得少的渠道，客户感受到的不是"渠道有差异"，而是"这家公司假装认识我"。

放在出海品牌身上，这个预期的源头大概率就是 Engagement Cloud 推送的一封邮件、Loyalty 引擎发的一条积分通知，或者 Commerce Cloud 主页那条个性化推荐。一旦客户被这些触点教会了"这家品牌懂我"，后面任何一个不接客户底座的 Agent，都在替整个品牌还债。

所以下一次有人问"我们要不要给客服上 AI Agent"——这道题答错的代价，比答慢的代价大。先去查一下：客服那个团队，能不能读到运营 App 已经看到的那 14 段飞行记录。
