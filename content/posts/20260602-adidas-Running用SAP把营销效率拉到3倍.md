前两天和一个做运动品牌出海的朋友吃饭，他正在愁一件事——APP 装机量做到几千万了，但真正打开的人越来越少。推送发了一堆，打开率倒着走。他问我，海外那些跑步类、健身类的 APP 是怎么把用户黏住的。

我想起一个老案例，正好聊聊。adidas Running App，就是 adidas 旗下原来 Runtastic 那个跑步 APP，全球用户 1.65 亿。他们用 SAP Engagement Cloud（也就是原来的 Emarsys）做实时触发的个性化推送，做了五年多了，算是用得很深的一个客户。

![adidas Running App](https://emarsys.com/app/uploads/2022/05/Runtastic-header-2280x900px.jpg)

## 为什么这个案例对出海团队有意思

先说成果。他们在 SAP Engagement Cloud 上跑出来的几个数：

- **活动效率提升 300%**——同样一个营销人，能跑出三倍的活动量
- **800 万次 APP 打开**由内容驱动而来，不是简单的"叫醒一下"，是用户因为内容相关才回来
- **200 多个数据点**用于内容优化，每条推送都在用细颗粒度的信号去筛人筛内容

这组数据放在国内做精细化运营的同行眼里其实不算炸裂。但有意思的是，它解决的不是"怎么发更多推送"，而是"怎么让推送变得不烦人"——这恰恰是出海运动健康类 APP 最难的一关。

## 他们之前卡在哪里

adidas Running App 的负责人 Edit Dudás 在采访里说得很直白。他们的难题不是"能不能发"，是这几件事：

- 用户横跨多个设备、多个端、多个 APP（adidas Running 和 adidas Training 是两个产品但用户重叠），消息口径要拉齐
- 个性化要规模化做，不能靠人工撞运气
- 推送必须基于上下文——一个人正在跑步、刚结束、还是已经三天没动了，给的内容完全不一样
- 多国家多语言，欧洲、北美、亚太一套规则跑不下来

这四条单拎出来都不新鲜，但叠在一起就是地狱。1.65 亿用户每天产生的运动数据是流式的、海量的，要在用户跑完一公里的那个瞬间触发一条相关的鼓励或推荐，传统营销自动化工具根本扛不住——延迟一分钟，那条消息就变成马后炮了。

## 方案思路：实时捕获、实时分析、实时触达

SAP Engagement Cloud 在这个案子里被选中的原因，Edit 说得也很坦诚——它能在毫秒级吃下用户的活动数据流，然后立刻判断"现在该不该推、推什么、用哪个通道"。这三件事一气呵成，没有传统 CRM 那种"先入仓、再清洗、再分群、再下发"的几小时延迟。

具体到落地，他们做了几件关键事：

- 把跑步、训练、装备、社区互动等所有触点打成一个用户旅程引擎，每个用户走在自己的轨道上
- 邮件 + APP 推送 + 应用内消息全部统一在一个工具里，营销人不用切五个后台
- 用 200 多个数据点（人口属性、运动频次、装备偏好、内容偏好等）作为内容个性化的输入
- 内容模板做成可复用的，多语言切换由系统按区域配置去渲染

这套架构的聪明之处在于把"营销人"和"工程师"解耦了。传统打法里，每加一个新的触发条件都要让数据团队加管道，营销人提需求等半个月。这套方案做完之后，营销侧拿点选式界面就能拼出一个新的实时旅程，工程团队不再是瓶颈。这个解耦才是 300% 效率提升的真正来源——不是工具变快了，是组织流转变快了。

## 出海团队能从这个案子拿走什么

先说一句不太中听的话：1.65 亿全球用户的体量，跟绝大多数中国出海运动品牌的盘子差几个数量级。所以照搬肯定不行。但是有几个判断点是普适的。

**第一，实时性的门槛不在于工具，在于数据架构能不能撑住。** 很多出海团队上 SAP Engagement Cloud 之后跑不出实时效果，不是工具不行，是后端事件流没建起来——APP 行为数据还在 T+1 出仓。这种情况先把事件管道（Kafka、CDP、流式 ETL）做好，营销工具才能跑出价值。

**第二，多语言多市场不能各搞各的。** 跨境电商和出海 APP 团队最常见的坑——德国团队一套模板、法国团队另一套、东南亚再来一套，三年下来素材库一团乱。adidas 这套做法是模板可复用、本地化由系统按规则渲染，运维成本低很多。出海团队从第一天起就该按这个方式建素材体系。

**第三，"能用"和"用得好"差三年。** 注意这个案子里 Edit 提到他们和 SAP Engagement Cloud 合作了五年多。前两年大概率是把数据接好、把人培训出来；后面三年才是真正用 200 数据点去做精细个性化、跑出 300% 效率提升的阶段。出海品牌评估这类工具的回报周期，不要按年算，按"产品成熟度曲线"算——头一年别期待奇迹，第三年开始才是收割期。

**第四，运动健康类 APP 跟普通电商在 CX 打法上完全不同。** 电商讲转化漏斗，运动 APP 讲行为陪伴。它的核心 KPI 不是 GMV 是日活月活、是用户能不能坚持。所以做这类业务出海的朋友，选 CX 工具时要看的不是"营销活动数据看得多漂亮"，而是"实时触发延迟有多低、行为信号能不能进得来"。这个评估标准，跟卖货生意完全不是一回事。

## 最后说一句

国内运动品牌出海这两年是个大主题，从安踏、李宁到 Keep、Yesoul，几乎都在看欧美市场。adidas Running App 这个案子最值得借鉴的不是某个数字，而是它把"营销自动化"做成了一个可以让营销团队自助迭代的产品平台——这种内部产品化的思路，远比买一套工具重要。

朋友饭桌上听完一直点头，说回去就把团队拉一起重新看下他们的数据管道。我说，先把"哪些事件没进系统"列出来，比讨论选什么工具更紧急。
