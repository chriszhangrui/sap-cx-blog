大家这阵子都在讨论 SAP 在 Sapphire 上有多激进——一口气把 Anthropic 抬进来当推理大脑、把 Dremio 收进来补湖仓、把 Reltio 焊进数据底座、再砸一亿欧元在生态上。看上去 SAP 像是要把企业 AI 这盘棋一个人下完。

但 SAPinsider 上 5 月 14 号的一篇分析把另一面挑明了：这其实是 SAP 第一次公开承认，企业 AI 这件事它一个公司搞不定。原文里有一句话很值得划下来——**"no single company will own enterprise AI"**。这话不是分析师说的，是 SAP 自己用合作伙伴名单写出来的。

这是个反直觉的转向。过去三十年 SAP 的故事都是一个词——"all-in-one"，从 R/3 到 ECC 到 S/4，一切都装在自家的盒子里，连 BI 都要自己造一套 BW。但你看 Sapphire 2026 的合作名单：推理交给 Anthropic 的 Claude，零拷贝数据交给 AWS Athena，跨厂商 Agent 互通让给 Google 和 Microsoft 的 A2A 协议，主权 AI 可选项是 Mistral 和 Cohere，可视化工作流编排买的是 n8n，安全运行时是 NVIDIA OpenShell，客服 Agent 外包给 Parloa，数据迁移工具拉上了 Palantir。

这个名单看一眼就知道——SAP 把自己以前要自己干的活儿，分了至少八份给别人。

## SAP 不是在拼算力，也不是在拼模型——它在拼"流程权威"

这是 SAPinsider 那篇文章里最关键的一个判断。原文用了一个词叫 **process authority**，翻译过来就是"流程权威"。意思是：在 AI 时代，超大规模云在拼算力，OpenAI、Anthropic 这些 AI 实验室在拼模型推理能力，但 SAP 拼的是另一样东西——它知道一张采购订单是怎么和供应商绑在一起的、一笔分录会怎么影响财务关账、一个工资单和合规之间的钩子在哪。

这听起来像废话，但它其实是一个非常聪明的定位。Anthropic 的 Claude 不知道你公司的 dunning level 是怎么配的；AWS 的算力不知道你那个 SOX 审计的 control 长什么样；NVIDIA 的 OpenShell 也不会替你定义"客户回款超过 60 天就触发 credit hold"这种业务规则。这些东西都在 SAP 那边，而且过去四十年它都在替全球大企业一行行 customizing 出来。

所以 SAP 这次不是在守 ERP 这块地，是在抢"控制层"。原文那句话很重——**"value is shifting away from standalone applications toward control layers that orchestrate data, models, and workflows"**。Klein 不再纠结"我们到底是不是软件公司"这个问题了，他要的是当那一层站在数据、模型和工作流中间发号施令的人。

## Customer Experience 这条线，逻辑同样成立

大家之前看 Service Cloud 把 Parloa 抬进来当语音 Agent，第一反应都是"SAP 把客服外包给别人了"。但如果按 process authority 这个框架去看，逻辑就反过来——Parloa 提供的是会说话的 AI 那一层，但客户的服务工单怎么 SLA、怎么 escalation、怎么和 entitlement 串起来、怎么从 case 跳到 spare part 订单——这些上下文 Parloa 是没有的。它必须接 Service Cloud 的 API 才能干活。

Commerce Cloud 这边新发的 modular cart and checkout services 也是同一个套路：把购物车、结算这些"可被替换"的部分变成 composable 模块，但定价、促销、Loyalty、税、库存、订单调度——这些"难替换"的部分还是焊在 SAP 这边。Sales Cloud V2 把 AI 嵌到 deal 推进的某一层，Service Cloud V2 给 case 重新分工，本质上都是在做同一件事：把推理外包，把流程留下。

这个布局对中国出海企业的 IT 决策者来说，影响其实是双向的。

## 中国出海品牌的 IT 决策者，到底要看清什么

这两年我跟做跨境电商的客户聊得比较多，一个反复出现的问题是——既然 Salesforce、SAP、Adobe 都在卷 AI Agent，到底押谁？SAPinsider 那篇文章给了一个挺现实的答案：**multi-cloud is no longer optional**。SAP 这次的设计假设就是你会同时跑在 AWS、Azure、GCP 上面，它的 A2A 协议是给跨厂商 Agent 互通用的，不是给你 lock-in 用的。

这件事对一家做欧洲市场扩张的中国制造企业意味着什么？意味着你之前在国内已经搭好的 Azure 数据栈不一定要重做，可以接到 SAP BDC 的零拷贝里去；你想用 Claude 做客户邮件分类，也不用专门为 SAP 再写一遍——只要有 A2A，Joule 那边的 Agent 就能调过去。

但坑也在这儿。原文里讲得很直白：**data architecture becomes the critical foundation**。在 SAP 这套新玩法里，零拷贝、Knowledge Graph、Joule Studio——这些东西落地的前提都是你的数据要"干净"。你那个 Salesforce CRM 里几百万条 lead 没去重、Service Cloud 工单的产品字段是手填的、Commerce Cloud 的 SKU master 和 ERP 那边对不上——这些问题在传统报表时代你还能扛过去，但 Agent 一旦上来执行，错一条数据可能就是错一个订单。

所以原文对厂商和 SI 的判断也很有意思——**"you are no longer just selling to a company. You are interfacing with its AI"**。意思是你以前见客户的采购，是和人打交道，可以解释、可以谈判、可以打感情牌。以后你的报价、SLA、合规材料是给客户的 AI Agent 看的，AI 不会和你寒暄，它只看结构化数据。这个变化对在中国做外贸的 ISV 来说，可能比"AI 替代销售"那种说法更值得认真对待。

## SI 合作伙伴的角色，正在被重新定义

还有一段 SAP 生态里所有 SI 都该读一下。原文说 traditional ERP implementation model 已经在演化——配置、部署不再是核心价值。价值现在在四个地方：设计 outcome 导向的 Agent 和工作流、编排多云多模型环境、管 AI 运维和治理、做行业垂直加速器。

翻译一下：以前 SI 是"实施者"，靠 ABAP 改吧改吧、Fiori 调调界面、SD 模块对个税码就能赚钱。以后 SI 是"orchestrator"，要懂哪个 Agent 适合哪个流程、A2A 怎么和外部系统对接、Knowledge Graph 怎么训出来贴客户的业务、出错了怎么 rollback。这套能力栈和过去十五年训练出来的 ABAP 老兵是不一样的。

中国这边的 SAP 生态合作伙伴，多数还在 RISE 迁移的红利里舒服待着，但这波转向其实给那些早做 BTP 扩展、早碰 Joule Studio、早把 CAP/Kyma 跑顺的小团队留了一个超车的窗口。窗口不会一直开着——SAP 生态里的人都看到 1 亿欧元投资了，谁都想分一杯羹，但能做"orchestrator"的人少。

## 最后一个反直觉的点

SAPinsider 文章结尾那段话其实很冷静：**"This is not a static partnership model. It is a dynamic ecosystem that will continuously evolve."** 这个生态不是签完合同就稳定的。Anthropic 今天是首选，明年可能加 OpenAI；Dremio 收进来了，Snowflake 那边的 connector 还在跑；Palantir 进来做迁移工具，但 Reltio 也在那边做 MDM。SAP 的生态从来不是干净的。

所以最后客户拿到的也不是一个"端到端无缝"的方案，而是一个"足够开放、足够受治理"的混合环境。你需要在里面做选择，需要懂在什么场景该用谁的能力。这件事看起来比当年装一套 R/3 累，但它的好处是——**你不用再赌一家公司**。

SAP 自己都不赌一家了，凭什么要客户赌。
