舞台上一位 H&M 的高管对着 AI 助手说：给我同事推荐一身合适的衣服。下一秒，SAP COO 从侧幕走出来，身上穿的就是 AI 推荐的那一套。

这是 SAP Sapphire 2026 上一段被反复传播的演示。但如果只把它当成一段秀，就错过了真正值得看的东西——**这家拥有 4,100 多家门店、横跨 81 个市场的瑞典快时尚巨头，到底是怎么把 SAP 这套东西用起来的**。

---

先打个比方。可以把 H&M 的 IT 系统想象成一栋 30 年历史的老百货商场。每一层都有自己的进销存、自己的收银、自己的会员卡，每一层之间靠对讲机协调。能开张，但每次大促都靠人肉熬夜。

现在 H&M 干的事情，相当于把这栋老楼的地基挖开，重新铺了一条公共主干网，再把每一层的小系统拆掉，统一接到这条主干网上。然后再在主干网上跑 AI Agent。

## 先把地基铺好，再谈 AI

H&M 的 CDIO Ellen Svanström 在台上把这层地基讲得很直白：RISE with SAP 提供云上的 ERP 底座，SAP Business Data Cloud 把分散的运营数据统一拉到一个池子里，SAP Commerce Cloud 把数字渠道和门店连成一条线，SAP SuccessFactors 管人和排班。**这四块东西不是各干各的，是焊在同一个数据模型上的**。

为什么这点重要？因为 SAP 在 Sapphire 上反复强调一句话——"再厉害的 AI Agent 也补不了一个糟糕的数据底座"。Klein 在主旨演讲里讲得更狠：80% 准确率对画独角兽够用，对企业级关键流程不够。

而 H&M 的故事，恰好就是这句话的反向证明：地基铺好了，Agent 才能跑起来。

## Store Intelligence Agent：店长的副驾

H&M 已经在用的第一个 Agent，叫 Store Intelligence Agent。它做的事情，店长以前每天上班都在做——只不过现在比店长快、比店长全面。

Svanström 给了一个具体场景：某场地区性的造型秀开始前一周，Agent 会扫一遍当地市场信号、近期门店流量、竞品动态，然后告诉这家店——这周应该把哪几款主打款放在 C 位、备多少件、怎么陈列。

关键是这条建议的来源。它不是某张 BI 报表，也不是哪个数据科学家手搓出来的预测模型。它是 **一个跑在 BDC 上、能同时读取供应链、财务、库存、本地市场信号的 Agent 网络**，输出的一条具体动作建议。

套用 Svanström 自己的原话：这不是一个 Agent，是一整套 Agent 在端到端协作。店长看到的那一行字，背后是一张网。

## Store Concierge：客户拿出手机的那一刻

第二个 Agent 还在开发中，叫 Store Concierge。它住在 H&M 的 App 里，但只在你走进门店的时候启动。

舞台上演的就是这个场景：让 Agent 推荐一套衣服给一个特定的人。Agent 给出的不是一张商品列表，而是 **一个考虑了个人偏好、当下场合、本店实时库存的具体搭配**。然后 SAP 那位高管换上这套衣服走出来。

这场 Demo 的尴尬之处在于：很多人把它当成噱头，但它真正想说的是另一件事——这套东西不是 ChatGPT 包了一层皮，它能调到这家店此刻还有什么号、什么色，然后再做推荐。

这一步背后真正要解决的，是 Commerce Cloud 和门店实时数据的"信号融合"。如果 Commerce Cloud 不知道这家店此刻库存，或者库存数据延迟两小时，这个 Agent 就废了。

---

## 这个故事对中国出海品牌的意义

H&M 的体量很特殊——4,100 家店、81 个市场。但中国做跨境零售、出海 DTC、跨国制造海外分销的品牌，正在面对的问题结构跟它一样：

- 多市场、多语言、多币种，每个国家的合规、税务、本地化都不一样
- 数字渠道（独立站 / 海外电商平台）跟线下渠道（海外门店 / 经销商）数据各跑各的
- 季节性极强，预测一旦失误就压一仓库尾货
- 总部和海外子公司之间的信息延迟，常常以"周"为单位

很多出海品牌的 IT 架构走到一定阶段就会卡住——不是因为缺 AI 工具，而是因为 **数据散落在七八个系统里，没有一个统一的"真相之源"**。这时候上 Agent，跟在沼泽里盖楼是一样的。

H&M 的解法不是"先买几个 Agent 试试"，而是 **先用 RISE+BDC+Commerce Cloud 把地基拼起来，再让 Agent 跑在上面**。这条路径长，但它解决的是结构性问题。

## 三个具体的判断

**第一，数据架构是 AI 的前提，不是 AI 的副产品。**这个顺序搞反了，后面所有动作都白做。

**第二，单 Agent 没意义，多 Agent 协作才有意义。**店长看到的那条建议，背后是供应链、财务、库存、市场信号四股数据的合流。把 AI 投资花在"再加一个聊天框"上，是浪费钱。真正值得投的是那种能跨流程、跨模块协作的 Agent 网络。

**第三，本地化粒度决定 AI 的天花板。**"今天东京涩谷店还有 M 码"和"今天日本市场有库存"，对一个 Concierge Agent 来说是两件不同的事。前者能驱动一次成交，后者驱动不了。这个粒度能不能做到，取决于 Commerce Cloud 和 BDC 之间的信号融合做得多紧。

SAP Sapphire 上每年都有 Demo。大部分 Demo 在散场之后就被遗忘了。H&M 这个 Demo 值得记一笔，不是因为那场换装秀，是因为它把"AI 跑在企业级 ERP 数据底座上"这件事讲得足够具体——具体到 4 个 SAP 模块、4,100 家店、81 个市场。

具体，是反 AI 模板化最好的武器。
