35% 实施工时砍掉，1 亿欧元给合作伙伴，50+ Joule Assistants 和 200+ 专精 agent 都已经 GA。这不是路线图，这是现在能买的东西。

但比这些更刺眼的一句话藏在合作伙伴生态的解读里：**"卖结果，别再卖正常运行时间。"**

某个做 SAP Service Cloud 多年的实施伙伴前几天发了一篇内部分享，把 Sapphire 2026 的关键点拆开看。他说一句话很扎心：过去十几年，SAP CX 项目的话术一直是"我有 200 个工程师，按人天报价"。从下半年开始，SAP 自己在告诉合作伙伴：**这套不行了，要改成"客户工单平均关闭时间"、"营销活动转化率"、"销售线索响应速度"这种 outcome SLA。**

听起来像是 SAP 终于"良心发现"，其实背后是一笔精明账。

## 项目交付逻辑被改了一半

先看 SAP 这次端出来的东西。

`Joule Studio 2.0` GA 了，这是开发 agent 的环境，配了 n8n 做可视化编排、Vercel 做设计工具、NVIDIA 做安全运行时。`Knowledge Graph` 把 SAP 五十年的 ERP 经验做成了机器可读的知识图——45 万张表、730 万个数据字段。然后是 `Joule Work`，新的工作入口——用户描述要什么，AI 处理工作流、数据、执行。手机端已经上线，Web 版本下半年 GA，桌面和语音也在路上。

这意味着什么？意味着 SAP CX 一个项目里，**配置工作的占比会大幅下降**。

举个具体的——某零售客户上 Service Cloud V2，过去要写 30 个 ticket routing 规则、20 个 SLA escalation 策略、再加无数 case category 配置，老老实实卖人天。现在 Joule Service Agent 自己会读历史工单、识别意图、推荐分流路径，配置工作量被砍掉一大块。

那钱去哪儿了？不是消失了，是**换了个名字**——从"配置费"变成了"agent 调优 + 治理 + 持续优化"。

## SAP 在重写合作伙伴的收入曲线

这事 SAP 自己看得很清楚。1 亿欧元给合作伙伴的基金，钱不是发给做"老式实施"的，是发给**部署 Joule Assistant、在 Joule Studio 上构建新 agent 的伙伴**。

合作伙伴生态的潜规则被改了几条：

1. 原来 SAP CX 项目的尾巴是 AMS——上线之后跑日常运维，按席位或按月收钱。现在被改写成"agent fleet optimization"，优化你这一队 AI 助手的表现。
2. 原来 SI 卖的是"我们能配 SAP"。现在 SAP 自己在告诉甲方：**SI 的核心价值是行业 know-how + agent 治理 + 决策审计**。配置技能不再是壁垒，因为 AI 自己就能做大半。
3. 交付节奏从"上线一锤子买卖"变成持续服务。"Autonomous Close in 90 Days"、"Time-to-First-Lead 缩短 40%"——这种打包产品开始替代传统 SOW。

对中国出海企业意味着什么？意味着选 SAP CX 的 SI 合作伙伴，**评估方式要变**。过去比的是"你做过几个 Sales Cloud 项目、有几个认证顾问"，从下半年开始要看：你的 agent 库存有多少？哪些行业场景已经预置好了？能不能签 outcome SLA？

## 但 outcome-based 真的能落地吗

这里有个矛盾点要说清楚。

按结果收费，听起来美好，实操起来一堆坑。我接触过的项目里，**最大的争议永远是"基线"**——客户说"现在我的工单平均关闭时间是 18 小时"，SI 说"我们做完降到 12 小时"，咨询费按差额收。但 18 小时怎么定义的？包括人工排查时间吗？复杂工单和简单工单一起算还是分开？基线一出问题，整个 outcome 模型就塌了。

更难的是**归因**。Service Cloud 上线之后客服效率提高了，是 agent 的功劳？还是因为客户同步把 IVR 换了？还是因为产品质量上来了所以工单本来就少？

SAP 这次给了一个工具叫 `agent 决策审计`，号称可以追溯每一次 agent 决策的依据和效果。听起来像是为 outcome SLA 量身定做的——把 agent 的贡献跟人工或其他系统的贡献拆开。

但工具是工具，能不能跑通还要看甲方愿不愿意签这种合同。

## 中国出海企业要做的两件事

如果你是在管全球 SAP CX 项目的甲方 IT 负责人，或者是做跨境电商、外贸、跨国制造的 CX 决策者，下半年要盯两件事。

**第一件**：重新审视现有 SI 的合同结构。如果合同还是按席位、按月、按人天收费，下个续约周期要谈 outcome 条款。即使最终保留按月费用为主，至少要在合同里加 KPI 联动的浮动机制——比如客户满意度低于阈值，下季度费用打折。这种谈判窗口期就是接下来 6-12 个月，过了 GA 高峰，议价权就反过来了。

**第二件**：把"agent 治理"作为新的内部能力建起来。Service Cloud、Sales Cloud、Engagement Cloud 各部署几个 Joule Agent 之后，谁负责监控它们的决策质量？谁审批 agent 的扩展？谁定义 agent 之间的协同规则？这件事在大多数中国出海公司里现在是空白。建议从 IT 部门拉一个跨 CX 三朵云的小组，专门做这件事——可以叫"AI 运营组"或者"Agent 治理委员会"，名字不重要，重要的是这个角色现在没人坐。

至于卖产品的视角，我的判断比较直接：**outcome-based 在欧美客户里跑得动，在中国出海客户里要看 CFO 接不接受**。中国甲方习惯按工时算账，把 SOW 改成"按客单转化率结算"，财务和审计第一关就过不去。所以更现实的路径，是混合结构——基础部分按月费，绩效部分按 outcome 浮动，给双方都留一个保险。

SAP 这次把模式给改了。但模式落不落得地，最终是一场博弈。
