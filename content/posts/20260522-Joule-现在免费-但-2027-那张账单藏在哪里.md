设想一下：某家中国出海消费品牌的市场总监 Lily，每周一早上 9 点要看 11 个 dashboard。Emarsys 那边昨夜的自动化跑了多少封邮件，Sales Cloud 上销售的高优先级线索堆了多少，Service Cloud 客户经理批的退货昨天卡在哪个环节，Commerce Cloud 上德国站点的转化率比英国低多少。她的 IT 副总裁告诉她，明年这些活儿会有"AI 助手"接管一大半。Lily 信。但她有一个非常具体的问题：如果这套东西 2026 年免费、2027 年开始按"动作数"收钱，那我现在该不该让团队大干快上？

Lily 这个问题不是矫情，是 SAP 在 Sapphire 2026 之后，留给所有 CX 客户的那道真题。

**SAPinsider 五月中旬出了一篇文章**，名字直白到有点暴躁——「你的 SAP ERP 刚刚长了 AI 大脑。然后呢？」正文不讲新功能，就摆 7 个问题，一句话挑明：未来 12 到 18 个月做的决定，会决定你这家公司剩下半个十年的位置。我把里面跟 CX 决策者直接相关的几条挑出来，结合最近接触客户的一些观察，重新讲一遍。

![SAP AI Brain](https://sapinsider.org/wp-content/uploads/2026/05/Gemini_Generated_Image_wez0shwez0shwez0.png)

**先说那个最让人不安的事实：免费窗口到 12 月 31 日。** Joule Studio 现在免费、Joule Agent Runtime 现在免费、AI Agent Hub 治理层 Q3 GA 之后免费纳入 Business AI Platform。这三件事拼在一起，意思非常清楚——SAP 现在缺的不是钱，是采用率。它要的是你 2026 年把 Agent 跑起来、把 ROI 数据攒出来、把流程改造的初版做出来。

2027 年的价格表呢？SAP 没说。Forrester 在自己的博客里直接点出来，绝大多数客户的 2026 预算里根本没建模 2027 那张账单。计费模型是按"actions"——每一个动作都要算钱，但什么算一个动作，目前还在含糊地带。一封 AI 起草的客户邮件算一个动作？背后的意图识别、语料检索、个性化拼接是一个还是四个？这件事在合同谈判桌上，每个字都是钱。

**用免费这半年建立你自己的 ROI 基线，2027 年再去谈价格的时候，你手里至少有数据。** 这是 SAPinsider 给的那条建议里我最认同的一句话。如果你 2027 年第一次坐到谈判桌前，凭"我们觉得这个有用"是谈不下来的。凭"我们去年跑了 80 个 Agent，覆盖了 23% 的 marketing 自动化场景，节省了 1.4 个 FTE"，那才有筹码。

**第二个问题更现实：还在 ECC 上没动的客户，怎么办。**

SAP COO Sebastian Steinhaeuser 的原话翻成大白话就是：Joule 是给云设计的。我们愿意陪那些已经下定决心要转型的客户走过渡期，但不是陪所有客户。RISE 客户合同里第一年三个 Joule Assistant 直接激活；ECC 但承诺迁移路径的客户能在过渡期摸到部分 AI 场景；ECC 完全没承诺的客户，AI 这条线基本上跟你没关系。

这话听上去冷酷，但 SAPinsider 那段判断我觉得是这两年我看到的最坦率的一句：**如果你既不在云上、也没有迁移承诺，你就站在 SAP AI 价值曲线的外面，每多站一年，成本就多复利一年。** 对中国出海企业里那些拖着 ECC 没动的甲方来说，这件事尤其要算一笔账：迁移工具能让 ERP 迁移工作量减少 35% 以上，Accenture 和 Palantir 的新合作专门针对复杂场景。所谓"按兵不动"的成本，其实从来都不是零。

**第三个问题，是数据。** 很多客户问"我们数据还没整理好，是不是先别动 AI"。这话听着保守稳妥，但其实是个伪命题。SAPinsider 给的框架我觉得很务实——数据准备不是前置条件，是和 AI 激活并行建设的能力。

三层架构是这么分的：前 6 个月把 Business Data Cloud 当成语义数据底座，把客户主数据、产品主数据、供应商主数据三件套先用 Syniti 治一遍——这三个是最容易让 Agent 出错的源头。6 到 18 个月引入 AWS 零拷贝集成把非 SAP 数据接进来，HANA Cloud 同时支撑向量、图、关系型、空间几种数据。再往后，Signavio 的 Company Memory 持续保证流程模型反映真实行为而不是当年画的 PPT。

关键是这句话：**让 Agent 路线图节奏，配合数据成熟度曲线。** 一个处理应付账款例外的 Joule Assistant 对数据成熟度的要求，远低于一个跨 50 家工厂的自治供应链 Agent。CX 这一侧也一样——一个处理订单退货状态查询的 Agent，比一个跨渠道做实时个性化推荐的 Agent 要好上手得多。先做容易跑出 ROI 的那个，别一上来就挑最难的。

**第四个问题，最微妙：人会被替代吗。**

SAP 自己讲的"三阶段"——人主 AI 辅、AI 跑人审、AI 自治——三步走的路径写在 keynote 里，听起来很有秩序感。但 Forrester 说了一句让人后背发凉的话："屏幕一屏一屏的 ERP 设计模式，会在 36 个月里过时，逼着企业重新思考用户培训、变革管理和信息架构。"

CX 团队会出现几个新角色：流程编排分析师、AI Agent 负责人、Joule 体验设计师。这些不是 HR 报表上的招聘新坑，而是说，你现在团队里那些"操作 Sales Cloud 的资深用户""调试 Emarsys 自动化的运营""排 Service Cloud 工单的 supervisor"——他们的工作内容会被切开重组。变革管理不再是项目里的一个工作流，而是一种持续能力。

具体怎么做？SAPinsider 给的几个动作我觉得务实：用 AI Agent Hub 里的 Joule Assistant KPI 反推每个角色受影响的程度，把员工的"覆盖纠正"动作设计成训练输入而不是错误，从高频低风险的任务开始让团队建立信任感。

**第五个问题，跟监管和合规有关。** 这条不是所有 CX 客户都要操心，但做跨境支付、做欧盟数据、做药品和医疗器械跨境销售的，必须看一眼。

Forrester 在自己的博客里把这件事讲得最狠："Claude 作为锚定模型，在受监管行业里 24 个月内会变成董事会层面的集中风险问题。"Joule 主推理模型是 Anthropic 的 Claude，但 SAP 也提供 Mistral AI 和 Cohere 作为主权可选项——这三个名字摆出来，是给那些有数据驻留要求的客户准备的。如果你做的是欧盟金融、做的是德国本地数据、做的是日本药品流通，模型选型这件事不能 SAP 默认推什么你就用什么。

SAP BDC 到 2026 年底会部署在 13 个 Azure 区域，包括德国和日本。这个数字看着是个数字，但对于在华跨国公司全球总部统一平台、对于做欧洲市场的中国出海品牌来说，意味着合规起点。SAP Autonomous Suite 是按 ISO 认证流程设计、为 SOX 审计兼容性设计的——不是说你不用做合规工作，而是说底子是有的。

**最后回到 Lily 的周一早晨。** 如果这一切都按计划落地，她未来 18 个月要做的事其实就三件：今年用免费窗口让营销团队跑出至少 3 个能算清 ROI 的 Joule Assistant 用例；明年初把这些数据装进合同谈判，把 2027 的"动作"计费谈到一个能预测的天花板；同时和 IT 那边一起，把客户主数据、订单主数据、产品主数据先治理到 Agent 能跑的程度。

她的周一早晨，可能从看 11 个 dashboard，变成看 11 个 Agent 当周的 KPI。听起来差不多对吧？但底层逻辑完全变了——之前她是在看流程跑了多少，之后她是在审 Agent 干得怎么样。前者她是操作员，后者她是治理者。

这个角色变化能不能完成，决定的不是技术上 Joule 跑没跑起来，而是像 Lily 这样角色的人，有没有趁着免费这半年，把自己往治理者那一步推过去。SAP 的钟已经开始倒数了。
