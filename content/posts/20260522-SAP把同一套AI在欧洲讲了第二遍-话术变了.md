Klein 在奥兰多讲完 Autonomous Enterprise，没歇几天，又把整套 PPT 拎到了马德里。同一个 Joule，同一个 Business AI Platform，同一个"50 多个助手、200 多个 Agent"——但话术换了一副。

奥兰多版本：AI 替你跑完整个流程。

马德里版本：AI 跑可以，但你得知道它在哪跑、用谁的模型、出事谁负责。

---

这事儿不是简单换个口径。它暴露了一个我做出海客户这些年最熟悉的画面——美国总部拍下来的方案，搬到欧洲分公司就要重谈一遍。不是产品变了，是甲方关心的东西不一样了。

## 第一层壳：AI 主权不是合规问题，是架构问题

SAP 把 EU AI Cloud 推上去之后，Madrid keynote 给出了三层部署模型：

- 公有云上跑，安全设置打满，常规企业够用
- 主权云：SAP 在客户所在区域里运营，受当地法规管
- 极敏感工作负载：政府、涉密——可以拉到客户自己机房落地

这套分层听上去像是给监管交差。但 Madrid 的 Q&A 上 Herzig 把话挑明了：**主权要写进 ERP 架构，不是项目交付完了再补一份合规清单。**

这话对中国出海的 CX 客户很有用。一家中国制造企业要把欧洲业务的 Service Cloud + Engagement Cloud 落地，过去的项目流程是：选型→实施→上线，最后法务跑出来盖章。现在 SAP 在告诉你——AI Agent 一旦进了工单流转、营销决策、支付链路，**数据驻留和模型出处必须在选型阶段就定下来**。等到 Go-live 才发现 Joule 默认调的是哪个区域的模型，那就是地基没打。

## 第二层壳：模型不是 Anthropic 一家说了算

奥兰多 keynote 把 Anthropic 推到了"主理性引擎"的位置——Claude 进 Joule，是默认大脑。

到了马德里，名字换了。**Mistral AI**——巴黎的 LLM 公司——被点名提供"主权模型选项"。再加上加拿大的 **Cohere**，跑在 SAP 自己的云基础设施上。

这步棋不只是分散风险。Forrester 之前那篇分析里提过 SAP "把宝押 Anthropic"的集中风险，Madrid 几乎是直接给出了答案：**区域不一样，可选的大脑也不一样。** 欧洲客户买 Joule，可以让它跑在 Mistral 上，请求不出欧洲。

还有 **n8n**——德国出来的工作流自动化平台，被嵌进了 Joule Studio，做可视化 AI 工作流编排。这事 SAP 之前花了 52 亿美元买下来不是白买的。Joule Studio 不只是一个 SAP 内部 Agent 的开发环境，它要变成"在 SAP 和非 SAP 系统之间编排 Agent"的地方。

这对中国出海做欧洲市场的卖家有什么意思？想象一个跨境电商品牌：Commerce Cloud 跑在欧洲数据中心，Service Cloud V2 接客服 Agent，Engagement Cloud 做营销自动化，外加自家的 PIM、ERP、WMS。Joule Studio + n8n 是 SAP 给的"我能把这些都串起来还能拿欧盟监管的胆"——前提是你得把数据流和模型路径在架构图里画清楚。

## 最关键的一层：分阶段自主

Steinhaeuser 在 Q&A 上回答得最长的一题，是关于"出错谁负责"。

SAP 给的答案叫 **staged autonomy**——分阶段自主。

- 第一阶段：Agent 跑，但每一步都有人审
- 第二阶段：人验证输出，可以回看动作
- 信心建立起来之后，再放更多权限给它

这模型不是 SAP 独创的——它就是大多数严肃企业用 AI 的真实节奏。但 SAP 把它写进了产品架构，意味着 Joule Studio 里你可以配置每个 Agent 的"自主度"，配套的审计、回放、权限边界是平台带的，不用 SI 重新写一套合规层。

Herzig 在这里又拿出一个对比，我觉得这是整场最值钱的一句话——**概率型 AI 跟确定型流程，要分开看。**

客服 Agent 给客户回答一个产品问题，准确率 90% 可以接受。但放到财务过账、医院药品配送、能源资产维修、工资发放——80% 都不够。Joule Studio 在做的事就是给 Agent 加业务上下文、加 guardrail、加确定性验证，让它能干 mission-critical 的活。

![Sapphire Madrid Opening Keynote](https://erp.today/wp-content/uploads/2026/05/SAP-Sapphire-2026-Opening-Keynote-1024x768.jpeg)

这话搁在 CX 场景里特别扎心——客服 Agent 90% 准确率没问题。但 Sales Cloud V2 里的 Agent 自动调价、Commerce Cloud 里的 Agent 自动改库存、Service Cloud 里的 Agent 自动发退款——**这些事的容错率根本不是 90%**。

## 仓库里那台机器人，可能比 Joule 更值得看

Madrid 还藏了个细节——SAP 在德国 St. Leon-Rot 的自营物流仓里，已经跑了 Cyberwave 的自主机器人，做装箱、打包、发货。背后串的是 SAP Logistics Management + BTP + Embodied AI Service。

为什么这事重要？因为它是 SAP 第一次把 Agent 从屏幕里拉出来。**同一个主数据、同一个流程上下文，能让数字 Agent 改单子，也能让物理 Agent 抓箱子。** 对做制造、零售、跨境物流的中国出海客户，这是个信号——你的全球分销网络里，下一代"工人"可能是 SAP 数据驱动的机器人。

## Steinhaeuser 那句没人转的话

Q&A 里他说了一句被大多数报道漏掉的——"客户告诉我们，SAP 的 AI 能力、数据上下文、治理，在我们自己的技术栈上太零散了，撑不起任务关键场景。"

这是 Business AI Platform 出现的真实原因。不是 SAP 想发个新产品，是 SAP 之前那一堆 Joule、Knowledge Graph、AI Agent Hub、Build、AI Foundation 摆在一起，客户实施的时候找不到主线——这个 Agent 走哪个数据源？那个 Workflow 用哪个治理引擎？换个 LoB 又是另一套。

Business AI Platform 不是新东西，是**把 SAP 自己之前那堆零散的盒子焊成一个**。这事远比"我们又上了一个 AI 平台"重要——它意味着以后所有 SAP CX 项目（Commerce/Sales/Service/Engagement）的 AI 部分，理论上都从这一个入口进。SI 不用再为每个 LoB 学一套 AI 工具。

## 写在最后

奥兰多和马德里两场 Sapphire 看下来，SAP 真正想推销的不是"自主企业"这四个字。是**"在你能控制的边界里给你自主"**。

对做欧洲市场的中国跨境品牌来说，这个差别决定了你的 CX 项目能不能落地。Engagement Cloud 调营销 Agent 用的是哪个模型，模型部署在哪个区域，出错的法律责任怎么走——这些以前是合规走廊里的对话，现在 SAP 直接把它们做成了选项。

下一步要看的，不是 SAP 又发了多少 Agent，是 staged autonomy 这套东西在中国海外公司的实际项目里能不能跑通。我赌大多数甲方第一年只会用第一阶段——人审一切。这反而是好事——AI Agent 不是越自动越好，是越能讲清楚每一步做了什么越好。
