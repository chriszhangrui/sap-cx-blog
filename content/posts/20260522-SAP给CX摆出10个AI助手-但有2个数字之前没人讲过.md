今天看到一条消息值得聊聊。

Isaac Sacolick 这个人，做了二十多年 CIO 圈的咨询，写过《Driving Digital》。他刚从 SAP Sapphire 2026 现场回来，写了一篇文章发在自己的 StarCIO 博客上，5 月 18 号发的。这篇没什么传播量，但里面藏着我看了几十篇 Sapphire 复盘文章里都没出现过的几个数字。

我把它挑出来跟你过一下。

## 一个零售 CDO 的非典型回答

Isaac 在现场遇到一位零售公司的首席数字官（CDO）。聊到 AI Agent 部署进度，对方甩了一个数字：他们已经部署了 1000 多个 AI agents。

SAP 自己一年前 Sapphire 2025 上发了 40 个 Joule agent，今年 Sapphire 2026 涨到了 200 多个。一家零售客户已经把规模做到了 1000+，意思是除了 SAP 提供的 200 多个出厂 agent，他们自己又造了至少 800 个。这个比例倒挂，是个很值得琢磨的现象。

> 说白了就是，SAP 的出厂 agent 是地基，但真正撑起业务的是企业自己长出来的那些。这件事改变了 SI 的活法——以前是部署、二开、运维，现在是帮客户从 50 个 agent 跑到 1000 个。

## CX 域里到底有几个助手

SAP 这次把 200 多个 agent 重新组装了一下，包成 50 多个 Joule Assistants，再分到五个域：财务（finance）、采购（spend）、供应链（supply chain）、人力（HCM）、客户体验（CX）。

Isaac 列出了 CX 域下面具体的 10 个助手，名字本身就是一份 Sales Cloud + Service Cloud + Commerce Cloud + Engagement Cloud 的功能切片：

- deal qualification —— 商机资质判断
- content —— 内容生成
- campaign —— 营销活动
- sales —— 销售执行
- deal closing —— 订单收尾
- shopping —— 购物引导
- merchandising —— 商品运营
- order management —— 订单管理
- self-service —— 自助服务
- case management —— 工单管理

如果你做过 SAP CX 的项目，这十个名字对应的就是销售员、营销经理、电商运营、客服坐席每天打开的那几个屏幕。SAP 没有再发明新工具，而是在每个角色背后塞了一个能干活的副手。

这个产品决策值得说一下：他们没叫"agent"，叫"assistant"。Isaac 的判断是，这个命名让员工不会把它当成"要替代我"，而是当成"我多了一个手"。员工愿意打开来用，比 agent 自己有多聪明更重要。

## SAP 公开的两个 CX 数字

文章里有两个 SAP 自己拿出来的 CX assistant 业务指标——这两个数字之前没在任何官方稿里看到过：

**+22%** —— expansion revenue rate 提升（客户扩展收入率）

**+15%** —— consideration to cart 转化率提升（从看到加购）

22% 是 Sales 那条线的指标，意思是用了 deal qualification + sales + deal closing 这套助手以后，老客户的复购和增购金额上去了。15% 是 Commerce 那条线，shopping + merchandising 助手让从浏览到下单的转化率往上抬了 15 个百分点。

数字本身先放一边——SAP 拿出来的指标，肯定是挑过的样本。但和之前 Joule 整体含糊的"提升效率 X%"比起来，CX 这次给了具体的业务环节定位。

对中国出海企业的项目而言，这两个数字更重要的意义是：你跟 CFO 立项时，可以挂在哪个具体的业务环节上去算 ROI。

## 治理跑得比创新慢，是这一年最大的风险

![现场分享](https://i0.wp.com/drive.starcio.com/wp-content/uploads/2026/05/IMG_2791-1600x698.jpg?resize=1600%2C698&ssl=1)

Isaac 在文章里花了挺多笔墨讲一件事——SAP AI Agent Hub。这个东西你可以理解成 agent 的"工商登记处"：所有部署的 agent，不管是 SAP 自己的还是第三方的，都要在这里注册，管理员可以监控每个 agent 的任务成功率、延迟、输出准确度、规则合规情况。

他给了一个判断：去年 CIO 的难题是"挑哪个 AI 实验做"，今年的难题是"deploy 之后的 agent 怎么管"。一个零售客户跑 1000 个 agent，没有 agent hub 你连出问题的是哪个都找不到。

做跨境电商的中国卖家如果在 SAP CX 上跑了三五十个 agent，治理这件事会比你想象的来得更早。Joule 出来一个错答案不是大事，但 deal closing 助手把折扣算错了、case management 助手把 SLA 等级判错了，事情就大了。

## Joule Studio 2.0 这一刀的真实意图

Isaac 把 Joule Studio 2.0 称为"皇冠上的宝石"——他自己说在很多平台上看过 agent 开发工具，SAP 的 spec-driven 开发方法（先写需求规格、再可视化方案、再生成测试）比大部分平台都成熟。

设计阶段免费用到 2026 年底。SAP 这步棋的意图我看是这样的：

- 降低你自己造 agent 的门槛——别老等 SAP 出新的 out-of-the-box agent
- 培育生态——让 SI 和 ISV 在 Joule Studio 上构建可商用的 agent，未来通过 AI Agent Hub 分发
- 挤压第三方 agent 平台的空间——既然在 SAP 上写代码免费，为什么要去 n8n 或者别的地方

对于在华跨国公司的总部对接人来说，这个免费窗口是个机会。趁这一年，把营销、销售、服务三条线上你最痛的几个流程，先做出 PoC——免费的代价是你自己得投人。

## 我的判断是

Sapphire 2026 这场 keynote 看下来，最容易被记住的是 200 多个 agent、Anthropic 合作、Knowledge Graph 这些大词。但 Isaac 这篇 CIO 视角的文章，把真正落地的几个问题挑出来了：

**第一**，命名比技术重要。"assistant"这个词决定了一线员工愿不愿意打开来用——没人愿意被 agent 替代，但很多人愿意接受多一个 assistant 帮忙。

**第二**，1000 个 agent 是已经发生的现实，不是未来。SI 合作伙伴接下来三年的活，不是再帮客户上线 SAP CX，而是帮客户把 agent 数量从 50 推到 500 再推到 1500，这是一个完全不同的服务形态。

**第三**，CX 那两个数字（+22% / +15%）值得记下来。下次你跟客户的 CMO 或者 CRO 立项的时候，这两个分母就是 SAP 官方背书的 ROI 起点。当然你得告诉客户，这是平均水平，不是承诺。

一句话——现在的 SAP CX，已经不是"我们卖一套软件给你"了，它在卖的是"一个能跟着你业务长出来的 agent 工厂"。区别就在这。
