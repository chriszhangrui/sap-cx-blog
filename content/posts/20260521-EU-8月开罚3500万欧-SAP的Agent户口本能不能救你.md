€3500 万，或者全球营收的 7%——欧盟 AI Act 给违规企业开的罚单上限，2026 年 8 月就要全面强制执行。覆盖范围正好压在 SAP 主战场：金融、人力、采购。

这件事对要在欧洲做生意的中国出海企业意味着什么？意味着部署在 SAP 上的那些 AI Agent，从几月几号起，就不再是"上线了能跑就行"的状态。每一个 Agent 在做了什么、谁授权它做的、出错怎么追溯，都要有一份能交给监管看的卷宗。

SAP 在 Sapphire 2026 上推出的 SAP AI Agent Hub，就是给这个问题准备的答卷。

## 为什么是 Hub，不是另一个开发工具

Agent Hub 是装在 SAP LeanIX 应用组合管理里的，不是独立产品。它做的事不是帮你开发 Agent，而是给你已经存在或将要存在的一堆 Agent 建一个户口本——不管是 SAP 自己的、Google 的、Microsoft 的，还是客户自研的，都登记在册，自动从各家仓库里发现并归档。

六项能力，目前两项已 GA，另外四项排在 2026 年 Q3：Agent 身份管理通过 SAP Cloud Identity Services、会话级别的可观测性、绑定业务 KPI 的性能监控，外加按风险评级和合规映射给每个 Agent 打标签。

> 这套架构有意思的地方在于双层关卡。Joule Studio 管"业务上该不该让这个 Agent 做"，OpenShell（NVIDIA 和 SAP 联合开发的开源运行时，嵌进了 SAP Business AI Platform）管"技术上能不能让它做"。前者是政策层，后者是文件系统和网络层的硬隔离。

为什么要分两层？因为只在应用层管控不够。一个有 shell、文件、网络、API 权限的 Agent，业务规则禁止它做某件事——但如果底层没有强制隔离，它依然可能从别的路径走过去。

## SAP 真正的护城河：四件已经在手的兵器

竞品要做 Agent 治理，得从外面拼装一套出来。SAP 的算盘是：架构地图我有 LeanIX，业务流程我有 Signavio，身份我有 Cloud Identity Services，组织架构我有 SuccessFactors。这四件东西本来就是 SAP 的存量资产，把 Agent Hub 焊在上面，竞品想追要重建四遍轮子。

这步棋下得很 SAP。它不在 AI 模型本身和 Anthropic、OpenAI 这些原生厂硬碰，而是把自己最不可替代的——五十年积累的流程、合规、组织上下文——拿来作为治理框架的根基。Klein 的原话翻译过来大概是：你可以拿别家的大模型来训练，但管这些 Agent 的那把钥匙，得从 SAP 这里拿。

## EU AI Act 把治理变成了"必答题"

这部法律有一条很多企业还没消化清楚：域外效力。意思是只要你的 AI 系统服务于欧盟客户，就算公司注册在中国、运营在新加坡，也得合规。中国出海品牌做欧洲市场的、跨国制造企业在德国有分销的、在华外资把全球 SAP 平台架在中国总部的——全部在监管半径内。

监管要看什么？审计轨迹得能拿出来、访问控制得能验证、人工兜底机制要落地、Agent 的权限要能快速吊销。任何一项缺位，处罚条款 Article 99 给出的数字是上限 €3500 万 或全球营收 7%（高风险违规则是 €1500 万或 3%），取高者。

> 最容易被忽略的一句话：监管要求的是"持续监控"，不是"上线时合规"。这意味着治理不是项目交付的一个里程碑，而是一条贯穿生命周期的标准动作。Go-live 之后，活儿才真正开始。

## 这件事对项目交付意味着什么

SAP 把审计基础设施和治理工具备齐了，但真正难的部分客户必须自己定义：审批矩阵、回退流程、精度阈值、谁有权吊销 Agent、异常该怎么升级。这些是设计活，不是配置活。

- 决策边界建模——这个 Agent 哪些事可以自己做，哪些必须报人
- 置信度阈值——低于多少分就要升级，需要带业务含义而不是技术参数
- 吊销路径——出事了，谁能在多长时间内把 Agent 关掉
- 审计交付物——Agent 注册表、风险分级、按 Agent 类型划分的审计规格、运营监控 runbook

这些活横跨业务、技术、合规三块，没法塞进任何一个传统项目流。它需要一个高级别的负责人单独立项，而不是配置完 Hub 就交差。配置 Hub 是任务，设计治理模型是工作流。

## 给中国出海 SI 和企业 IT 的几条具体建议

SAP 公布了 €1 亿的伙伴生态投入，Joule Studio 2.0 在年底前免费开放——这个窗口期很关键。中国出海企业和服务它们的 SI，可以从这几个方向切入：

- 先把团队配置出来——一个有合规素养的资深功能顾问握设计权，一个 BTP 或 LeanIX 架构师做技术配置，一个变革管理专家管交接。三个人的小队就能跑大多数中型治理项目。
- 把治理当订阅服务卖，不是当项目卖——季度 KPI 漂移评估、年度法规更新审查，做成可以复购的服务包。一锤子买卖没法满足"持续监控"的法规要求。
- 简历和项目说明要换个写法——以前写"配置了什么"，现在要写"承担了哪些决策"：权限怎么分布在人和系统之间，治理产出物长什么样，升级路径怎么设计的。

> SAP 历史上每一波创新，都会留下一道治理鸿沟。S/4HANA 留下的是 Clean Core 的客制化债务，云迁移留下的是安全和集成的治理空白。Agentic AI 留的也是一道，但这次时间窗口被法规强行压缩了——监管不会等企业自己慢慢成熟。

前 20 个 Agent 是谁帮客户治理的，后面 100 个就还会找这个人。和当年第一批做 S/4HANA、第一批做 BTP 架构的顾问一样，跑得快的人定的不是单价，是接下来几年的整个市场基准。

SAP CX 的项目里也跑得通这条逻辑。Service Cloud 上的客服 Agent、Sales Cloud 上的报价 Agent、Engagement Cloud 里的营销自动化 Agent——每一个都涉及客户数据访问权限、决策授权、客户沟通的合规留痕。在欧洲市场上线 CX 平台的中国出海品牌，治理这一栏不补齐，平台跑得越好，风险敞口越大。

## 最后一句

如果你最近在做 SAP CX 项目、要在欧洲上线 Agent 类能力——把"治理工作流"作为一个独立的工作包提出来，明确它的负责人、交付物和持续运营责任。哪怕只是先在 LeanIX 里把现有 Agent 登记一遍，也是一个能在客户面前说清楚的起点。

€3500 万的罚款风险压在头顶，再不动，不是技术问题，是经营问题。
