有个独立分析师叫 guptadeepak，做了一个叫 **CIAM Compass** 的项目——把市面上所有客户身份产品（CIAM）拉到同一张表里打分。前几天他更新了 SAP Customer Data Cloud 的评测页，最后核验日期是 2026 年 4 月 22 日。

看完之后说实话有点复杂的感觉。一边是夸——20 年 B2C 同意管理的老底子，没几家能比。另一边是劝退——非 SAP 客户别考虑，DX 跟不上、价格也太狠。

这种来自体系外的"中立打分"，其实比 Forrester 那种宏观魔力象限更值得拿来对客户讲。因为它具体到 API 有没有、Terraform Provider 有没有、能不能对接 OneTrust，全是销售场上会被问到的问题。

## 先把它的结论摆在桌上

这位评测人的判断分两段，他自己用了"右选/错选"两个词来概括：

- **右选**：已经在用 SAP Commerce Cloud 或 SAP CX 套件的客户。CDC 的 Gigya 基因加上和 SAP 这边的集成深度，让它在这种场景里值这个钱。
- **错选**：绿地评估、非 SAP 生态、想让开发团队跑得快的项目。DX 落后加上极高的入门价格，把这些客户拒之门外。

这个判断很多老售前心里其实早就有数了，但有人系统性地把它写出来贴到网上，意义不一样。客户来问"为什么我们要选 CDC"或者"为什么我们不选 CDC"，你手里就有一份第三方文本可以引用。

## 夸的部分：20 年同意管理是真功夫

评测里反复提到一个词——**purpose-specific consent**，按用途分别同意。这个东西做过 GDPR 项目的人都知道有多麻烦。客户为了营销邮件勾的同意、为了产品改进勾的同意、为了画像勾的同意，得分别记录、分别撤销、分别走审计。

SAP CDC 的前身 Gigya 从 2006 年就在做这件事，2017 年被 SAP 以 3.5 亿美金收下。这部分的成熟度在评测里被列为整张表上最强的一块——同意管理 + 偏好中心 + 渐进式画像，三件套打通。

所以如果你的客户是金融、医疗、保险、电信这种监管行业，**"按用途分别管理用户同意"是一个硬合规要求**，CDC 是有真正护城河的。

> 评测原文里说："Twenty years of B2C CIAM experience, uncommon depth on consent management."（20 年 B2C CIAM 经验，同意管理上的深度在业内罕见。）

## 批的部分：DX 真的有点跟不上

这块更值得我们注意。评测在"开发者体验"这一栏列了一堆"无"——

- 无 GraphQL API（只有 REST）
- 无官方 CLI
- 无 Terraform Provider
- 无本地 emulator（开发时只能连云端环境）
- 扩展模型还是 WebSDK + 自家 Site Extensions（专有 JS）

这些放在 5 年前不是问题，因为没人这么要求。但今天的客户技术团队，已经习惯了"基础设施即代码"那一套——身份配置应该能用 Terraform 管、本地能跑模拟、CI 能自动化。Auth0 / Okta / Stytch 这些对手在这一块走得明显更前面。

评测里还提到一个更值得思考的点——**SAP CDC 在 Agentic 身份能力上几乎是空白**。MCP 支持没有、动态客户端注册没有、Agent 与人 Token 隔离也没有、Web Bot Auth 也没有。

等等，这里有意思了。SAP 整个集团从 Sapphire 开始，一直在喊"Autonomous Enterprise"——AI Agent 要进核心系统、要替员工干活。但 Agent 真要干活，它得有自己的身份、得能被授权、得能被审计。这块控制平面从哪里来？目前的 CDC 评测来看，**这部分能力还没在产品里落地**。

## 价格那一栏，把不少客户挡在门外

评测里给了一个估算：100 万 MAU 大约 4.5 万美金一个月，年化 50 万美金以上。10 万 MAU 也要 8500 美金一个月。10000 MAU 以下连标价都没有，得直接走 SAP 大客户销售流程。

评测人的总结很直接："Pricing typically among the highest in the index, six-figure annual minimums standard."（属于整个评测序列里最贵的那一档，六位数美金的年度起签是常态。）

这就是为什么我们在中国市场推 CDC 经常觉得吃力——很多客户的全部 IT 预算可能都不到这个数。CDC 不是一个"用一点试试"的产品，它是 SAP 大单子里的一块，要靠整个 CX 套件的故事来撑。

## 评测把 CDC 的定位卡得很死

看完整篇评测，最有价值的不是评分，是它把对手关系也梳理清楚了：

- 现代化对决：SAP CDC vs Auth0——客户在新老技术栈之间做选择
- 老牌企业 CIAM 同行：Ping Identity、ForgeRock、Oracle IDCS、Akamai Identity Cloud

注意它没把 SAP CDC 跟 Stytch、Clerk、Supabase Auth 这种新兴方案放在一起比——评测人觉得不在一个赛道。这其实暗含了一个判断：**SAP CDC 是给传统大企业准备的产品，它不参与开发者社区的那一战**。

## 给同行的几句话

跟客户讲 CDC 的时候，几个我会主动说的事：

第一，**同意管理深度是真的**。如果客户在乎合规、在乎按用途切分授权、在乎能跟 OneTrust/TrustArc 这种 CMP 串起来，CDC 是稳的。

第二，**DX 这块要提前打预防针**。客户的开发团队如果是"基础设施即代码"那一套，要在评估早期就让他们知道——现在没有 Terraform Provider，自动化要靠 REST API 自己包。

第三，**Agentic 身份这块，目前是产品 roadmap 而不是已交付能力**。Sapphire 上 SAP 给 Agent 画了大饼，CIAM 这边的控制层什么时候补上来，是值得跟产品团队再确认的事。客户问到 AI Agent 怎么登录系统、怎么被审计，别硬讲。

第四，**价格这件事不要绕**。如果客户预算明显不到那个数，及早把对话引向是不是先用其他方案先跑起来，等业务规模上来再换。SAP CDC 不适合"先小后大"。

独立第三方愿意花时间评测，本身就说明这个赛道在被关注。Klein 喊 Autonomous Enterprise，但用户的身份和同意还是这一切的前门。门没装好，里面跑再多 Agent 也是裸的。
