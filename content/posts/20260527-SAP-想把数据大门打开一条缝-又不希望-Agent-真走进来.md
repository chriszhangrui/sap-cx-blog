今天看到一条消息值得聊聊。

TechTarget 5月22号那篇 David Essex 的稿子，标题挺直白：*Disrupted by AI, SAP grapples with exposing its ERP data*。说的是 SAP 在 Sapphire 2026 上一边喊"自治企业"，一边又在三周前发了个新 API 政策——禁止第三方自治 Agent 通过非批准通道访问 SAP 数据。

Diginomica 联合创始人 Jon Reed 在文章里给了个判断：**"这是 SAP 历史上最大的一次转变，比互联网那次还大。"**

## 把这件事翻译成大白话

说白了就是：SAP 现在站在一个尴尬的十字路口。

一头是它最大的资产——按 SAP 自己的话，全球大约 **80%** 的商业交易跑在它平台上。这是 53 年攒下来的家底，是 AI 时代谁都搬不走的护城河。

另一头是 AI 工具不停在敲门。Anthropic 的 Claude Cowork、Google 各种 Agent 编排工具、Boomi 和 ServiceNow 的流程治理层，都在抢一个位置：**企业 AI 的"门面"。**

Reed 在原文里说了句直白的：*"所有人都想做那个能调度别人家东西的人。"*

## SAP 的两难，画出来是这样

![SAP 数据策略两难](https://www.techtarget.com/rms/onlineimages/ai_a311883856_searchsitetablet_520X173.jpg)

原文有个特别精彩的类比，TechTarget 的作者直接把这事比作戈尔巴乔夫——一边推 glasnost 开放，一边推 perestroika 改革。开放那部分大致成功，但改革推得太急、太猛，结果失控。

这个类比的辛辣之处在于：SAP 现在面临的，不是"要不要开放"的选择题，而是"开放节奏怎么把控"的工程题。

## 技术上 SAP 给的答案是 BDC

SAP 数据分析负责人 Irfan Khan 在 Sapphire 给了个比较坦诚的说法。他先承认了一句话——SAP 过去十年大概收购了 **$55-60B** 的 SaaS 公司，Ariba、Concur、SuccessFactors、Emarsys，每个都有自己的数据模型。光是把这堆数据语义对齐，就够 SAP 内部折腾很多年。

这种"内部数据整合"的活，反而成了 SAP 应对 AI 时代外部数据需求的肌肉记忆。Business Data Cloud（BDC）就是那个产物——把 ERP 和那些 SaaS 应用的数据模型在一个层面上拉齐。

里头两个关键点，对做 CX 的人特别值得看：

- **Data Products**：把销售订单、供应商主数据这种企业核心记录，预先打包成"数据产品"，里面带着算法和元数据，可以直接被 BDC 共享。这个对 SAP CX 的产品组合（Commerce Cloud、Sales Cloud、Service Cloud、Engagement Cloud、CDP）是结构性利好——它们终于有个统一入口跟 ERP 对话。
- **Zero-Copy 共享**：数据不用物理搬运，BDC 给 Snowflake、Databricks、AWS 这些环境授权访问，就像 SharePoint 那样。Holger Mueller（Constellation Research）在邮件里跟原作者说，这背后还有更狠的——HANA Cloud 要并入 BDC，让 Agent 有事务性数据库可以直接写。

这一步如果走通，意味着外部 AI 不只是"读" SAP 数据，而是能在 SAP 自己的环境里"写"——这才是真正的开放。

## 但矛盾的地方就在这里

Sapphire 前三周那个 API 政策，把口子收回去了一些。第三方自治 Agent 不能直接访问 SAP 数据，必须走批准通道。

Reed 的原话比较直接：*"客户一旦发现你设了数据收费站，就会很恼火。"*

这件事我接触的客户里也有反映。一个做跨境电商的 IT 负责人前阵子问我：他用 Anthropic Claude 接 SAP Sales Cloud V2 做销售辅助，按现在政策得走 SAP 的批准通道——这是不是意味着以后他想接 OpenAI、想接 Mistral，每接一家都得 SAP 点头？

这个问题没人有标准答案。但站在客户角度看，**"开放"这件事，不是 SAP 单方面定义的，是客户用脚投票出来的。**

## "自治企业"这个词，分析师有保留

Sapphire 还把整个战略包装成"建设自治企业"（autonomous enterprise）。这个词在原文里被几位分析师质疑了。HR 分析师 Josh Bersin 直接说"这不是最好的信息（not the best message）"。

Reed 的判断是：客户想做的不是"自治企业"，而是**"按自己节奏自动化关键流程"**——这两件事不是一回事。前者听起来像是把人替换掉，后者是给人减负。员工层面对前者的抗拒会很大。

Joshua Greenbaum（Enterprise Applications Consulting）则提了个更扎心的问题：Sapphire 给了大量"理论上的用例"，但真正在跑、真正出 ROI 的客户案例不多。他原话是——*"AI 价值和基础转型价值，怎么分得开？这会是个非常非常大的问题。"*

说白了，很多客户的所谓"AI ROI"，其实是把流程梳理好了的红利，不是 AI 本身的红利。

## 对中国出海企业 CX 决策者意味着什么

几个我看到的实操层影响：

- **选型侧**：如果你正在评估 SAP CX 落地海外业务，BDC + Zero-Copy 不是 IT 部门的玩具，是 CX 应用能不能调到 ERP 数据的关键开关。早点把 BDC 列进选型清单，别等部署到一半才发现数据层卡脖子。
- **架构侧**：第三方 Agent 接入 SAP CX（特别是 Sales Cloud V2、Service Cloud V2）的合规通道，目前是 SAP 自己定的。在中国出海企业全球总部部署时，IT 架构师要预留"批准通道"评审环节——别先做了集成方案才发现要走审批。
- **合作伙伴生态侧**：原文提到 SAP 这次拿出 **€100M** 投给 AI 合作伙伴，鼓励他们做"颠覆性应用"。SI 朋友们，这一波是真金白银，谁能率先把 BDC + Joule Studio 跑出可复制的 CX 实施方法论，谁就抢到下一阶段的方法论制高点。

## 我的判断是

SAP 这次的"开放节奏"会反复横跳——这是必然的。一边是市场逼着它把数据让出来，一边是它必须保住自己作为"数据中枢"的位置。每一个新政策、每一个新接口，都会在这两个力之间摇摆。

原文那个戈尔巴乔夫类比有意思的地方在于：glasnost（开放）和 perestroika（改革）不能完全分开。开放数据但不重新设计 API 治理结构，结果就是失控；只改 API 政策但不真的开放数据，又会被客户抛弃。

SAP 这次至少看出来想认真解这道题。BDC、Zero-Copy、HANA 入 BDC、Agent Hub、€100M 生态投资——这些都是配套动作。但这道题没有一两年看不出真章。

对客户来说有一句话值得记住：**不要听 SAP 在 Sapphire 上讲什么，要看它在每个季度的 release 里实际开放了什么 API。**

那才是数据大门到底开了多大缝的真实尺子。
