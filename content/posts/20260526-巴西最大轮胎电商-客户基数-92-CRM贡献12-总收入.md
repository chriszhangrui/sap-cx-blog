如果你是做出海或者跨境电商的，下面这个场景可能很熟悉：营销团队同时跑邮件、短信、WhatsApp、广告，每个渠道一套工具，数据都是岛。BI 周报里看到复购率在掉，但要回答"哪批人值得再投一次"，光是把数据拼齐就要一周。等数据拼齐了，机会窗口已经关了。

巴西有家叫 PneuStore 的轮胎电商，是当地 B2C 轮胎赛道最大的玩家，2006 年成立，到现在线下直营点 240+ 家，背后是 Cantu Inc 控股。他们去年用了一年时间把这个事重新做了一遍，结果是客户基数增长 92%，复购增长 10%，CRM 渠道直接贡献了总收入的 12%。今天聊聊他们怎么搭的。

![PneuStore](https://emarsys.com/app/uploads/2025/09/hero-customer-story-PneuStore-scaled.png)

## 一、痛点不是技术问题，是看不见客户

轮胎这个品类很特殊。客单价不算低，但购买频率拉得很长——一套轮胎用三五年很正常。这意味着两件事：第一，单次获客成本必须算到几年的 LTV 里才合算；第二，复购窗口非常稀疏，一旦错过就得再等三年。

PneuStore 当时面临的问题列出来很普通：行业竞争变激烈、客户决策路径越来越复杂、复购率上不去、想做实时互动但跑不起来。这几个问题任何一个 DTC 品牌都能对号入座。麻烦的是这些问题相互纠缠——你要做实时互动得有干净的数据底座，要提复购得知道客户车型和上次换胎时间，要做精准投放得能把 CRM 里的人群同步给广告平台。一个环节卡住，整条链就跑不通。

## 二、解决方案：SAP Engagement Cloud + Sinch 双引擎

PneuStore 选的组合是 SAP Engagement Cloud（原 Emarsys）做 AI 驱动的营销自动化和客户数据，加上 Sinch 做多渠道消息触达。这个搭配在拉美市场挺常见——SAP Engagement Cloud 出策略和分群，Sinch 出 SMS、WhatsApp 这类高送达渠道的通信能力。

具体跑起来的逻辑是这样：

- **用 AI 看懂客户偏好。** SAP Engagement Cloud 里的预测分析模型在分析客户行为，比如"这个客户开 SUV，上一套买的是越野胎，距上次购买 28 个月"，模型据此给出下一步动作建议。
- **按车型设计 Journey。** 团队设计了基于轮胎尺寸的客户旅程，意思是不同车主进系统后看到的内容是不一样的。这个看着简单，但真要落地需要把车型数据从订单系统、客服记录里抽出来灌到分群里，工程量不小。
- **API 实时同步。** SAP Engagement Cloud 和 Sinch 之间走 API 双向同步，避免出现"暗数据"——就是采集了但激活不了的那部分。这是这个方案里我觉得最值得抄作业的设计。
- **31 个 active customer journey。** 包括复购、首单、弃购挽回、欢迎和升单。这个数量级对一个轮胎品牌来说挺克制，但每条都打得很准。

## 三、成果：硬数字

> **客户基数增长 92%**——从合作 SAP Engagement Cloud 和 Sinch 之后算起，活跃客户池子接近翻倍。

> **耐用品复购率 +10%**——这个数字在轮胎行业很难做，因为复购周期天然长，能撬动 10% 说明客户车型预测和触达时机做对了。

> **CRM 渠道贡献 12% 总收入**——这是把营销自动化做成业务条线之后才有的数字。CRM 不是成本中心了，是收入来源。

## 四、几点判断

先说一个我做 Engagement Cloud 项目时反复踩过的坑：很多团队上 MA 工具的第一年都会做 50+ 个 journey，第二年开始砍。PneuStore 一开始就只跑 31 个核心场景，把每个跑透——这个克制是对的。journey 数量不是绩效，转化才是。

第二个判断是关于 SAP Engagement Cloud + Sinch 的搭配。在拉美和东南亚这种 SMS、WhatsApp 触达率远高于邮件的市场，单靠 SAP Engagement Cloud 自带的渠道是不够的，必须叠一层本地化的通信网关。Sinch 在巴西是合规且稳定的选择。如果你是中国出海品牌打东南亚，Sinch、Twilio 或者本地的 CPaaS 选一个就够，不要让品牌团队自己一个一个国家对接运营商。

第三个判断是给到出海团队的：12% 收入来自 CRM 这个数字背后藏着一件事——营销自动化能不能做成业务条线，不取决于工具，取决于公司里有没有人对"CRM 收入"这个指标负责。PneuStore 的 Growth Marketing Manager 公开把这个数字摆出来，说明这是有 OKR 顶着的。中国出海品牌经常买了工具但没人背指标，最后跑出来的 dashboard 给老板看一眼就关了。

最后一点提醒，Engagement Cloud 在中国大陆没数据中心，PneuStore 这套架构能直接复用的对象是有海外业务的中国品牌——比如做汽配出海、做跨境零售的。纯内贸的公司想抄这套架构得换思路，国内有自己的合规栈。

## 回到开头那个痛点

"复购率在掉，但说不清哪批人值得再投一次"——这个问题的本质不是缺工具，是数据散在三个系统里、没人有权限把它拼起来、就算拼起来也没人对结果负责。PneuStore 的 92% 客户增长不是 SAP 给的，是他们自己把数据底座、AI 分群、多渠道触达、KPI 归属这四件事按顺序做完了。

所以关键不是工具选哪家，是上工具之前先把"谁对这个数字负责"问清楚。
