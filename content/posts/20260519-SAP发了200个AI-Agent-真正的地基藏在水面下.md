大家都在算 SAP 这次发了多少个 AI Agent。50 多个 assistant、200 多个 agent、26 个行业版本，加起来够开一个数字员工运动会。但盯着这些数字看，反而会错过 Klein 在 Sapphire 2026 上塞进 Autonomous Enterprise 架构里最关键的一块——那块东西不长在水面上，叫 **Company Memory**，公司记忆。

SAP 自己画了一张 AI 冰山图。水面以上是公开的 LLM 能干的事——写文案、生成图片、写代码，这些训练数据互联网上都有。水面以下，才是企业真正的命根子：你的合同条款、你的 SLA、你和某个大客户三年来谈出来的特殊定价、你的供应链异常处理流程、你的合规边界。这些东西没有任何公开模型见过，也没法靠 prompt 临时教会。

![The Autonomous Enterprise SAP Sapphire 2026](https://s4hanaguide.com/wp-content/uploads/2026/05/The-Autonomous-Enterprise_SAP-SAPPHIRE-2026-1024x576.png)

Klein 在 keynote 上有句话挺扎心的：消费级 AI 答错了无所谓，企业级 AI 答 80% 对就是不及格。这个 80% 的差距藏在哪？藏在水面下那些没人写下来的部落知识里。一个做了十二年的客户经理脑子里装的"这个客户每年 11 月一定要提前备货""那个海外分销商付款总要拖一周但绝对不能催太紧""欧洲那条线退货率永远比北美高 3 个点"——这些东西从来没进过 ERP，也没进过 CRM，但它们才是业务真正怎么跑的逻辑。

**SAP 这次是想把这些"水面下的东西"做成一个系统层。** Company Memory 被定义成一个 contextual intelligence layer，喂给 Joule 和那 200 多个 Agent。它要装的不只是 ERP 里的结构化数据，还要装组织里的隐性知识——异常处理的判断、跨部门协同的潜规则、特殊客户的特殊处理逻辑。配上 Knowledge Graph 把字段和字段之间的关系连起来，再叠上新发的 SAP 自研 domain model（在 SAP 代码上训练过，理解 ABAP 业务逻辑）和刚收购完的 Reltio 主数据治理工具——整个 context layer 就立起来了。

为什么这件事对中国出海企业的客户体验决策者特别重要？因为客户体验是企业里"水面下知识"密度最高的领域之一。

举个例子。一家中国制造企业在德国、墨西哥、东南亚同时铺了渠道，每个市场的退换货政策、本地法规、节假日促销节奏、KOL 投放习惯、客服话术口径都不一样。德国客服得守 GDPR，墨西哥的 Tier 2 经销商有特殊返点协议，东南亚的 Lazada 大促节奏跟欧洲 Black Friday 完全不是一个体系。这些事情从来没有谁能写成一份完整文档——它就活在区域负责人的头脑里、活在客服 leader 的处理记录里、活在某个 SI 顾问七年前留下的口头交接里。

如果你只是给 Service Cloud 接一个 LLM，这个 LLM 永远学不会这些区域差异。它只会用最通用的回答给客户写邮件——然后德国客户被冒犯，墨西哥经销商觉得被怠慢，东南亚的售后纠纷一夜爆三十条投诉。这就是 Klein 反复强调"80% 不够用"的真实场景。一个不知道你德国分公司有什么本地承诺的 Agent，去自动回复客户的诉求，是真的会把生意干掉的。

![SAP Sapphire 2026 Keynote](https://news.sap.com/wp-content/blogs.dir/1/files/2026/05/12/SAP_SAPPHIRE25ORL_14708.jpg)

Company Memory 想解决的就是这个。它把那些隐性知识结构化、版本化、权限化，变成 Agent 调用业务数据时的语境层。说白了，让 AI Agent 不只是"知道客户的订单状态"，而是"知道这个客户的订单状态在你们公司应该怎么处理"。这两件事差着十万八千里。

**但这里也有个让人有点警觉的地方。** 一旦 Company Memory 成了 Agent 调度的入口，它就成了企业最关键的资产之一。SAP 把它做成 SAP 体系内的产品意味着——你的隐性业务知识从此活在 SAP 的 context layer 里。这层东西的可移植性、可审计性、跨厂商互通能力，会变成客户体验选型最关键的一道考题。SAP 自己也意识到这事敏感，所以在 Sapphire 上反复强调 governance：审批链、合规边界、人工兜底。但具体到落地时，给客户的客户体验 Agent 配多深的 Company Memory 权限，敢不敢让它独立答复一个百万级欧元客户的退货请求——这才是真正难的判断题。

Klein 还讲了一个比较聪明的策略，叫 Bridge Strategy——你不需要先把所有系统都迁完云、清完 core，才能开始用 AI。绝大多数客户都还跑在 ECC、跑在 hybrid 环境里、跑在一堆历史包袱上面。SAP 这次的姿态是承认这个现实，让 AI 当那座桥。对中国出海企业其实是个好消息：你不用先把全球客户体验体系全部推倒重建才能动 Agent，可以从某一条业务线、某一个区域市场开始接 Joule，逐步把这条线的 Company Memory 沉淀下来。

这种"渐进式落地"对做 Sales Cloud V2、Service Cloud、Engagement Cloud (Emarsys) 的客户都有意义。比如 Emarsys 这条线，Engagement Cloud 本身已经在做行为数据驱动的客户旅程编排，下一步把跨市场的营销规则、合规要求、品牌话术口径喂给 Company Memory，让 Agent 帮你自动生成符合本地语境的 campaign，这个故事就比单纯讲"AI 自动写邮件"扎实得多。

Sapphire 这次最值得记的一句话不是"我们发了 200 个 Agent"，而是 Klein 说的那句——"未来的企业不只是记录业务怎么发生，还要让业务自己跑起来"。要让业务自己跑，前提是 AI 真的懂业务。懂业务的前提，是把那些没人写下来的水面下知识变成可调用的层。这件事 SAP 这次给了路线图，但具体每个客户体验项目要怎么把自家公司的"部落知识"系统化沉淀下来——这是接下来一两年里相关项目团队真正要一起啃的硬骨头。

Agent 数量是个抓人眼球的故事。Company Memory 才是决定故事能不能跑起来的地基。
