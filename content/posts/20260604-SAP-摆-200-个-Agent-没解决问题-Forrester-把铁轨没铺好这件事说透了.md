Forrester 6 月 3 日发了一份新报告，给所有押注 Agentic AI 的厂商递了一记冷水。

三分之三的企业领导者说自己在做 Agentic AI，真正跑在生产环境里的只是一小撮，能跑通多 Agent 协同的更是凤毛麟角。这个差距，就是 2026 年企业 AI 真正的故事。技术像一列失控的火车，企业是它后面那节沉重的车厢。

## 在追的多，能抓住的少

Forrester 这次访谈了一批正在搭 Agentic 系统的架构师，又翻了自己手上的企业调研。给出的判断很直接：技术已经到了，企业的准备度没跟上。这不是新故事，过去十几年每一次大技术浪潮都是这个剧本。但这一次的难题是，准备度还有没有可能追得上一辆这么快的火车。

长周期 Agent 不再是路线图上的事。OpenAI 内部已经跑了几个月以 Agent 为主、几乎不用人干预的软件开发流；Cursor 部署了能连续运行的编码 Agent；Anthropic 演示过跑好几天的研究型 Agent。能力到位了。问题在于——一个能连续跑好几天的 Agent，行为不像聊天机器人，更像一个分布式系统。它需要编排、需要身份、需要上下文纪律。这些东西，绝大多数企业从没建过。

![Forrester：在追的企业很多，真正抓住的少](https://go.forrester.com/wp-content/uploads/2026/06/Figure_1-SO-agentic-AI-2026.png)

Forrester 还点出一个细节：Agent 规模化的失败原因，几乎不是 Agent 数量太少，而是任务复杂度没人管理。把十几个 Agent 七拼八凑接起来，没有共享注册表、没有统一路由，最后协同就垮成重复劳动和漂移。每一个 Agent 都做了一点事，加在一起没人知道结果是什么。

## 追是便宜的，抓住才是贵的

兴趣到处都是，规模化少之又少。原因相当一致，第一道坎就是钱。ROI 算不清把企业卡在了 Pilot 阶段——大多数公司没法把"窄场景效率提升"翻译成"上生产的理由"。这跟我观察到的 SAP 客户实际情况几乎一致：客户搭了一两个 Joule Agent 跑得不错，但要往上推就开始问"省下的人天能换成账单上多少钱"，问到这一步基本就停了。

第二道坎是治理。超过一半的企业说，即便采用了 NIST AI RMF 框架，Agentic Sprawl（Agent 失控蔓延）依然存在。原因不复杂——一份政策文档管不住一个会自己调用工具的自治系统。第三道坎是平台之争：到底押 SaaS 自带的 Agent，还是 SI 帮你拼出来的，还是自己从零搭。这场争论本身就在冻结决策。

> 所有这些问题底下，还有一笔"信任税"。每一次自治动作都得被记录、得能向审计员解释清楚。当下这个成本太高。连 Bank of New York 这种走在最前面的受监管企业都还没拿到 Agentic 承诺的全部价值——但 BNY 有个绝大多数公司没有的东西：一支已经准备好管自治 Agent 的员工队伍。这种准备度，才是金子。

## 真正的瓶颈是风险管理

Forrester 2026 安全调研里，49% 的安全决策者把 Agentic AI 列为关注项。这些威胁不是程度上的变化，是种类上的变化。Agent 之间可以互相冒充、可以提权——因为非人类身份这件事现在还是一团乱麻。Agent 数量增长比谁能跟得上的速度都快。一旦协同断了，一个小判断错就能变成一次故障。

不能用季度审查来管这种系统。要管它，就得用"在 Agent 跑的同时也在跑"的仪器；身份和策略不能停留在文档里，得作为代码强制执行。这一点正好和 SAP 在 Sapphire 上反复强调的 Agent Hub、AI Agent 治理那套打法对得上——SAP 自己很清楚，把 Agent 推上生产之前，这道地基躲不过去。

## 怎么开始追上这班车

Forrester 给的处方比较朴素——领先的企业不是 Agent 数量最多的，是把铁轨先铺好的。三件事最重要：

- **先投编排，再加 Agent。** 共享注册表、交接模式不可少，否则 Agent 和老系统永远拼不到一起。
- **重设工作流，不是只换工具。** 把 Agent 螺丝刀拧在人类节奏的老流程上，只能省点工时，省不出价值跃迁。挑几条高摩擦流程，把角色、审批一起重做。
- **把每一个 Agent 当作有身份的实体来治理。** 独立凭证、最小权限、完整日志、有名字的 Owner 管它的生命周期。不允许"无主自治"。

然后分阶段铺。先从带审批门、带回滚路径的有界任务开始；只在控制力跟得上的时候，才把自治范围放大。

## 写在最后

这份 Forrester 报告的价值不在新闻性，在于它给所有 Agentic AI 厂商的故事递了一面镜子。SAP 在 Sapphire 摆出 200 多个 Agent，把"自治企业"喊成了主旋律。Forrester 这边给的数字是：少数企业真正抓住了。两件事并不矛盾——SAP 的产品确实在到位，但客户能跑多快，受限的不是 SAP 的能力，是企业自己的编排底座、治理纪律、员工准备度。

中国出海企业现在面临的问题就更具体一点。在跨境电商、跨国制造、海外分销的 SAP CX 项目里，要把 Joule、Sales Cloud V2、Service Cloud V2、Engagement Cloud 的 Agent 串到一起跑，第一道坎不是产品功能，而是项目里有没有人想清楚 Agent 之间怎么交接、出错的时候谁兜底、合规审计追得到哪一层。这正是 Forrester 这份报告反复在讲的——铁轨没铺好之前，火车跑得越快越危险。

SAP 客户 9 月、10 月谈预算时，建议把"再上几个 Agent"和"先把编排底座补齐"放在同一张优先级表上。不要只看产品演示里 Agent 跑通了什么，先问一下自己——这条铁轨，有没有人在铺。
