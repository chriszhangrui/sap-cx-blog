今天看到一条消息值得聊聊。

SAP CX 总裁兼首席产品官 Balaji Balasubramanian 亲自下场写了篇博文，讲的是 SAP Customer Experience Q1 2026 这一波到底更新了什么。表面上看是常规的季度发布概览，Sales Cloud / Service Cloud / Commerce / Engagement Cloud 一路捋下来，但读到一半我意识到，这次的口风不太一样。

原话是这么说的：**AI alone is no longer a differentiator**——光有 AI 已经不算差异化了，关键在于 AI 在哪里干活。说白了就是，Joule 那种站在用户面前的助手，这一波在 SAP 内部的产品逻辑里已经退到第二层了。Q1 里真正铺开的，是把 AI 焊进报价单、产品描述、服务工单、营销分发这些实际执行流里。

**第一个值得看的点：Email to Quote。**

销售在 Outlook 里收到客户邮件，过去要切到 Sales Cloud 找客户、查 SKU、挂报价单，一通操作下来 20 分钟起。Q1 这一版直接在 Outlook 加载项里把 SKU 解析、报价单生成做完，销售点几下就发出去了。这个功能短期看是节省时间，但中长期它把 Sales Cloud 的入口从 SAP 自己的界面挪到了 Microsoft 那边。

这就是 SAP 这一年在反复讲的 **Joule + Microsoft Copilot 互通** 落地的第一个真业务场景——之前都是讲 PPT，现在终端用户能用上了。

**第二个：Deep Research for Sales。**

销售经理做大客户拜访前要写客户简报。过去这事要么自己花一晚上，要么塞给售前团队。Q1 里这个能力把 Sales Cloud 的客户数据、Service Cloud 的服务历史、外部市场情报合在一起，直接出一份能用的客户 brief——行业背景、新闻、SWOT 都有。这个功能的潜台词是：SAP 已经默认你会同时部署 Sales Cloud 和 Service Cloud，数据底座是 BDC 那一套。如果你只买了其中一个，这个 Deep Research 的效果就会打折扣。

**第三个：Media Attachments for Product Descriptions。**

这个看着不起眼，但对做跨境电商的中国卖家是个真活。你的产品手册、规格书是 PDF，过去上 Commerce Cloud 之前要人工提炼成商品描述，中英文还要再做一遍。Q1 这版用 AI 直接从 PDF 里抽信息，生成结构化的商品描述，既给消费者看，也喂给搜索引擎和 agentic commerce（就是 AI 帮消费者下单的那一类前端）。

我看到的项目里，出海品牌跑欧美 D2C 的，光做产品上架就能耗掉运营团队三分之一的时间。这个功能落到位，直接打开了 Commerce Cloud 在新品上架节奏上的瓶颈。

**第四个，Service Cloud 这边，Digital Service Agent 终于把交接做顺了。**

过去 conversational AI 自助答疑和真人 case 创建是两套系统。客户在聊天框里说半天，真要开工单的时候人工坐席还得重新问一遍意图、产品型号、问题描述。Q1 里 DSA 能自动总结对话意图，把工单字段填好，然后无缝交给 Service Cloud。这个能力听起来朴素，但它真正解决的是 SAP 一直被诟病的"AI 助手是助手，后台还是手工"的割裂问题。

**第五个：Agent Inbox。**

Service Cloud 里给坐席一个统一的视图——case、task、service order 全在一个 inbox 里，带工作量可视化。我看到的客户里，做高端家电、跨国零售品牌的服务团队最关心这个。过去坐席要在三四个标签页之间切来切去，Q1 这一版把**单视图调度**摆出来了。这是 Service Cloud V2 这两年一直在做的方向，Q1 终于把界面层做完了。

**第六个：Engagement Cloud 这边的两个 AI 能力。**

一是 SMS 渠道的 AI Assisted Report Builder——你在 Engagement Cloud 里直接用自然语言问"上个月 SMS 收入多少"，系统给你算。二是 Mobile Push 的 AI Segments，预测哪些联系人未来 30 天会互动、会沉默、会彻底流失，营销人按预测结果做触达。

![AI Report Builder for SMS](https://news.sap.com/wp-content/blogs.dir/1/files/2026/04/14/SAP-Cuxstomer-Experience_Q1-2026_AI-assisted-Report-Builder-SMS-and-Condition-2026-01-28.png)

*SMS 渠道的 AI Assisted Report Builder / 来源：SAP News*

这两个能力一起看，本质是把 Engagement Cloud（原来的 Emarsys）从"批量营销工具"往"预测式营销执行"推。出海做跨境电商的中国卖家如果用 Engagement Cloud，过去最大的问题是分群粗，要么发太多被骂，要么发太少错过窗口。这个 AI Segments 功能把"下次发给谁"的决策从规则匹配换成了概率预测。

![AI Segments for Mobile Push](https://news.sap.com/wp-content/blogs.dir/1/files/2026/04/14/SAP-Cuxstomer-Experience_Q1-2026_AI-Segments-for-Mobile-Push-2026-01-28.png)

*Mobile Push 的 AI Segments / 来源：SAP News*

**还有一个容易被忽略的：Retail Intelligence（早期采纳客户）。**

这个能力是把零售供应链规划、执行、客户互动焊成一条回路——人和 AI agent 一起做计划、调价、调库存。中国制造企业海外分销网络做品牌出海（比如电动工具、家电、户外用品）的，这个能力出来之后值得跟踪。它的逻辑是把 S/4HANA Retail Cloud（零售行业 ERP 核心）和 CX 这边的 Commerce、Engagement 用 AI 串起来。Q1 还在 Early Adopter，Sapphire 上要专题讲。

**最后一个事：Advanced Success Plan 现在覆盖到 Sales Performance Management 和 Enterprise Service Management 了。**

这事我之前单独写过一篇，这里不展开。但放在 Q1 整体看，SAP 是把"卖软件 + 卖服务包"的边界往 CX 全产品线推。SAP 在中国的 CX 项目里，这个 ASP 服务包对甲方意味着：别想着自己摸石头过河了，买了 SAP 的产品就要配套买 SAP 的咨询和加速服务，SI 在中间能拿到的项目份额会变化。

**我的判断是这样的：**

Q1 这一版 CX 更新的真正信号，不在于发了多少新功能。而在于 SAP 把 AI 的位置从**用户身边**挪到了**流程当中**。Email to Quote 不是给销售加个聊天助手，是把 AI 钉在"客户邮件—报价单"这条具体执行链上。Digital Service Agent 不是再造一个聊天框，是把对话意图直接焊进 case 创建。这个方向跟 Klein 那篇"AI 军备竞赛方向错了"是一脉相承的——SAP 在赌的是，下一个阶段的差异化在 AI 跟流程的耦合深度，而不是模型本身。

对中国出海企业的 CX 决策者来说，这一版有两个动作可以考虑：一是看看 Commerce Cloud 上的 Media Attachments 能不能把你跨境上架的瓶颈解开；二是用 Sales Cloud + Outlook 的 Email to Quote 看一看你海外销售团队的报价响应时长。**这两个能力都不需要重新做架构，Q1 直接能用。**

做跨境电商和出海 D2C 的 SI 合作伙伴，这一波要重新看一下你给客户的 CX 实施 SoW——很多功能 Q1 已经原生交付了，过去靠定制开发卷起来的服务收入，这一波要让位给 ASP。这是 Klein 这一年反复讲的"从按人天到按结果"在 CX 落地的第一个具体场景。
