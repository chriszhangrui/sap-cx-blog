> E3 Magazine 总编 Färbinger 用一个机场比喻把这二十四个月的 SAP 战略说清了。

假设有这么个画面：一个 SAP 老客户站在机场行李带前等自己的箱子，眼前一只一只漂亮的、可能很值钱的箱子滑过去，都不是自己的那个。

这是 E3 Magazine 主编 Peter Färbinger 给当下 SAP 创新流写的开场白。等等，这个比喻有意思。它不是说 SAP 没在做事，恰恰相反，SAP 这二十四个月做的事多得装不下：Sapphire Madrid 摆出 50 多个 Joule 助手、200 多个 AI Agent、SAP Business AI Platform、Joule Work、SAP Knowledge Graph、Autonomous Suite。问题不在数量。问题在于客户来这个行李带前等的，是自己那个 ERP 问题的解法，那只箱子始终没出现。

从做 CX 项目的客户视角看，这个错位更明显。一个做跨境零售的中国出海企业，跑 Commerce Cloud 加 Sales Cloud V2，要的可能就是订单一致性、退货流程更顺、客服 Agent 别讲错话。Sapphire 主舞台上滚过去的是 Anthropic、Nvidia、Parloa、n8n、Dremio、Reltio、Prior Labs、LeanIX、WalkMe，一长串名字，哪个能解决他下周要上线的那个促销价回写问题？

## 这二十四个月发生了什么

Färbinger 的拆解很冷静。他用了一个词叫 panic-driven U-turn，被金融市场逼出来的恐慌掉头。

原本叫 North Star 的那个架构愿景刚摆上桌没多久，现在新的目标画面叫 Autonomous Enterprise。换名字是表象，真正变的是底层逻辑。

SAP 缺一块东西：自研的基础 AI。这件事得说出来。Klein 在最近一次采访里也间接承认过，AI 战略八九个月前刚刚做过一次方向调整。所以接下来这家公司能做的，就是两件事，买和合伙。

买的清单：数据查询引擎 `Dremio`、主数据平台 `Reltio`、做表格基础模型的弗赖堡初创 `Prior Labs`。再加上之前的 LeanIX、WalkMe、SmartRecruiters。

合伙的清单更长。Anthropic 的 Claude 接进 Joule，Nvidia 的 Llama-Nemotron 跑复杂推理，Google、Meta、Mistral、Microsoft、Perplexity 的模型通过 BTP 上的 Generative AI Hub 给客户选。数据层加上 Databricks 和 Snowflake 跟 BDC 互通。CX 这一侧的两个外援，一个是 n8n，后来直接战略投资了，用来做 Joule Studio 里的可视化 Agent 编排，另一个是 Parloa，专做联络中心的 AI 对话，嵌进 Service Cloud V2。

## Knowledge Graph 这块拼图为什么重要

Färbinger 在文章里挑出来一件事讲：SAP Knowledge Graph。

这是个语义层。它的作用是把 SAP 数据库里那些晦涩到不近人情的字段名字、表名、外键关系，翻译成 LLM 能读懂的业务语义。如果没有这一层，模型对着 `VBAK-VBELN` 是不知道这是销售订单号的，自然就会胡说八道，这就是大家常说的 hallucination。

所以 Knowledge Graph 是 SAP 自治企业战略里少数的真自研件。它把 SAP 几十年的业务知识沉淀下来，这件事别人复制不了。CX 项目里做 Sales Cloud V2 报价、Service Cloud V2 工单分类、Engagement Cloud 的客户分群，凡是要 Joule 接业务上下文的场景，都得过 Knowledge Graph 这一层。

但 Färbinger 也提到 DSAG 德国 SAP 用户协会的预警：Autonomous Enterprise 这套愿景目前主要还是营销，engine room 里那些老系统比如 Ariba、Business Network 仍然在跑老逻辑，只是被加了一层 AI 装饰。

## API 政策这扇门

这一段才是最值得 SAP 客户警觉的。

SAP 推出了一套新的 API 政策，严格限制外部 AI 服务怎么访问 SAP 系统的数据。表面叙事是安全和合规，Färbinger 给的另一种解读是：SAP 在用 API 政策圈地，把客户更深地推进自己的 BDC 加 Datasphere 生态。

对一个跨境电商客户意味着什么？假设这家公司本来用 Snowflake 做数据仓库，想用一个第三方 Agent 平台直接读 Commerce Cloud 的订单数据，现在这条路要么变窄，要么变贵，要么被引导到 BDC 的零拷贝集成上。表面看起来更整洁，实际是数据控制权交出去。

Forrester 之前也表过一个相近的态度，SAP 想成为企业 AI 的数据守门人，但钥匙锁在自己口袋里。现在 Färbinger 这篇相当于把这件事从产品视角又过了一遍。

## Joule Work 是新前端，也是新黑箱

Joule Work 这件事 Sapphire 上讲了，但很多人没意识到它的颠覆性。

用 Färbinger 的话：传统的表单、菜单树、事务码 T-code 走进历史，用户用自然语言描述意图，Joule 在后台自己调起对应的 Agent 把活干完。

对一个销售人员来说听起来很好，不用记 VA01、VA02 那一串了，直接说"给这个客户开个 5000 件的订单"。但反过来想：如果一个 Agent 主动决定从哪个仓发货、用什么定价、走哪条审批流，而它走的那一条逻辑你看不见、改不动、复盘不了，这就是黑箱。

Färbinger 引用 SAP 社区里的一个判断：营销跑得比技术成熟度快得多。Joule 在真实业务里还经常给错答案，在那些历史悠久的客制化数据库里失败得很难看。

做 CX 项目的人对这件事应该有共鸣。Service Cloud V2 上线 50 多个 AI 助手听起来威风，真到一个客服坐席每天接 200 通电话的场景，哪个 Agent 在后台帮她改了什么、出了错谁负责、升级路径是什么，这些工程问题比舞台上的演示难得多。

## 真正的成本陷阱

这一段直接挑明了 Färbinger 的核心担忧。

SAP 传统的软件许可是按用户算的，多少个销售用 Sales Cloud，按 named user 收钱。如果未来 AI Agent 接管了人的知识工作，这套许可逻辑自动贬值。SAP 给出的应对是 pay-per-AI usage，按 AI 消耗收费，单位是 AI Unit。

SAP Community 里有人翻出过一个价签：`1 AI Unit = 7 €` 给客户，`0.65 €` 给合作伙伴。

从一个出海企业 CFO 的角度看，这是一个完全没法预算的账单结构。Agent 跑得越多，钱花得越多。某个 Service Cloud Agent 把工单分类做得很到位，一年多用了几千次，账单是多少？没人能提前告诉你。Gartner 早就发过预警，让客户上 AI Agent 之前先把 chargeback 模型想清楚，不然 AI 账单会上 autopilot，自动驾驶式的烧钱。

Färbinger 的话术更直白：Autonomous Enterprise 有可能"突变成一个无法测算的、永久的成本陷阱"。这话有点重，但方向值得信。

## 量子计算那段烟雾

Färbinger 顺手把 QUTAC 也讲了一下，SAP 跟 BASF、BMW、Bosch、西门子合伙搞的量子技术应用联盟。

他直说：这是一个"战略烟雾弹"，用来转移大家对 SAP 在主营 ERP 和 AI 上还没补齐的功课的注意力。当 E3 杂志去问 SAP 在 QUTAC 里到底要做什么具体的事，答案是含糊的。

这个判断听起来尖锐，但有它的道理。一个做客户体验项目的甲方，被推荐去关心量子计算未来如何优化全球供应链的最优仓储路径，优先级排序排得比客户的退货流程还高，这事确实有点错位。

## 站在客户这一侧，怎么读这篇文章

Färbinger 这篇不是反 SAP 的檄文，它的态度更像是：Klein 很努力，也很有野心，但这家公司缺一个稳定连续的战略，每个月都在生一个新的 ERP 想法、一个新的 AI 产品、收购一个新的初创，客户跟不上这个节奏。

中国出海企业做 SAP CX 项目，这个观察可以转化成几条具体的判断。

- 看 SAP 路线图时，先把"营销侧 AI 演示"和"工程侧 AI GA"分开。Joule Work、Knowledge Graph 这些是真在演进，但落到 Sales Cloud V2、Service Cloud V2 的具体功能，哪些 Q3 真能跑、哪些只是 PRD，必须在合同前问清楚
- API 政策那道门是真的，给跨境业务的数据架构留 plan B。如果你的客户数据要进 Snowflake 或者 Databricks 跟 BI 团队联通，现在就要算清楚走 BDC 零拷贝是合算还是被锁
- AI Unit 这个计费维度，在写 business case 的时候必须算两份：按用户算许可的旧账本，和按 AI 消耗算的新账本。两者并存的过渡期可能比想象中长
- Joule Work 是个 5 年趋势，不是 1 年项目。客户内部 IT 准备好"用自然语言驱动 Agent"这套新交互之前，旧的菜单和事务码不会一夜消失。把它当一个长期方向来培养能力，不是当年内必须上的功能
- Parloa、n8n、Anthropic 这些外部伙伴，决定了 CX 在 AI 这一侧的真实能力边界。挑型号的时候要把这些供应商的 SLA、可用区、数据驻留都看一遍，不能只看 SAP 一家

## 回到那只箱子

Färbinger 文章最后一句其实留了一个温和的问号：The time to move fast is now, isn't it？

该快，但快得有判断。客户在行李带前等的那只箱子，始终是自己那个具体的业务问题，promotion 回写、订单一致性、客服质量、忠诚度积分双向同步、报价审批提速。SAP 摆出来的那一长串漂亮箱子，有些是真能装，有些是装样子。

这件事得自己分。SAP 不会替你分。
