前几年大家爱举的一个类比是：电商平台就像商场，商家把柜台搬上去，消费者自己走进来逛。

现在剧情有变化。AI Agent 开始替消费者跑腿——你跟它说一句"帮我下单一双 42 码的跑鞋"，它就替你完成搜索、比价、下单的全过程。这就像商场里来了一群带任务的代购，他们不需要看橱窗，也不需要点按钮，他们只想知道一件事：你的接口在哪里、参数怎么填。

---

之前在公众号里写过几次，SAP 在这张牌桌上明显是个旁观者。Salesforce、Shopify、Adobe 这些选手都已经出招——Marketing MCP Server、Agentic Storefront、AI Shopping，都在抢"AI 替消费者下单"的入口。SAP Commerce Cloud 看起来一直没动。

但 6 月初看到 AIMultiple 的一篇盘点，里面提了一句话，让之前的判断要打个折扣——

> "At NRF 2026, SAP announced a Storefront MCP server for SAP Commerce Cloud, planned for Q2 2026."

翻译过来：今年 1 月的 NRF（全美零售联合会）大会上，SAP 已经悄悄宣布了 Commerce Cloud 的 Storefront MCP Server，落地节点是今年第二季度，也就是**现在**。

## 这件事到底有多大

先解释一下 MCP 这玩意儿。Model Context Protocol 是 Anthropic 去年 11 月开源的一个标准，简单粗暴的类比是——它相当于"电器插座"。以前每个 AI Agent 接每个企业系统都要写定制的接线板，现在大家都用同一个标准的插头，AI 能统一发现"这家系统提供了哪些能力""怎么调"。

Storefront MCP Server 的意思是：SAP Commerce Cloud 的商品目录、库存、价格、下单接口，都按 MCP 标准暴露出来。AI Agent 不用打开网页、不用模拟浏览器点击，可以直接调用接口完成"搜商品 - 取价格 - 加购 - 提交订单"的全流程。

这件事对 Commerce Cloud 客户的意义，类比一下就是：原来你的网店是开在淘宝里的，需要消费者主动来逛。现在你的网店多了一个"批发档口"，AI 可以直接进来询价、下单。两套门店都开着，看哪边客流大。

## SAP 这步棋为什么之前看不见

第一个原因，发布场子选错了。NRF 是零售圈的大会，Sapphire 是 SAP 自家旗舰大会，5 月 Sapphire 那波铺天盖地的 200 个 Agent 把所有人的注意力都吸过去了，1 月 NRF 上的这个 MCP server 发布就被淹没了。

第二个原因，SAP 自己也没大力宣传——它不像把 Joule 在 Sapphire 主舞台上展示那样大张旗鼓。原因可能很现实：MCP server 这种东西本身没有 demo 价值，它是个开发者接口，不像聊天框可以拿来表演。

第三个原因，可能更微妙。SAP 一边在收紧"外部 AI Agent 调 SAP 数据"的政策（可参考 5 月底关于 API Policy v4 的一系列讨论），一边在 Commerce Cloud 这条线上又主动开了一个 MCP 入口。这看起来矛盾，但其实是分场景的策略——B2B 后台数据该锁还得锁，B2C 商品目录这种本来就要给消费者看的东西，开放给 AI 反而能拉流量。

## 配套的还有 A2A，这才是真正的远期

原文里还提到一个东西：A2A，Agent-to-Agent 互操作协议。

类比一下 MCP 和 A2A 的区别——MCP 是"AI 调系统"，A2A 是"AI 调 AI"。前者解决的是 Agent 怎么调用一个 ERP/CRM 的接口，后者解决的是 Agent 怎么和另一个 Agent 沟通、分工、协作。

放在 Commerce Cloud 的场景里：买家那边可能是 Google Shopping 的 AI 代理、OpenAI 的 Operator、或者亚马逊的 Rufus；卖家这边是 SAP Commerce 上挂的一个 Agent。两边的 Agent 要谈成一笔交易，光有 MCP 不够——MCP 只解决"我有什么能力"，谈判规则、合同协议、退款流程，需要 A2A。

SAP 同时在推 MCP 和 A2A，意思是它不打算只做卖家这一头。它想做的是**两边 Agent 谈判时的中间协议层**。这个野心比一个 MCP server 大多了。

## 中国出海卖家应该怎么看

SAP Commerce Cloud 在国内有数据中心，但跨境电商和 D2C 的客户更多是把它部署在欧美区域的 AWS 或 Azure 上。

如果你是做出海的电商品牌，这件事的意义有两层：

- 短期：你的 Commerce Cloud 实例在 Q2 2026 之后可能直接拿到 MCP 能力，这意味着 ChatGPT、Claude、Perplexity 这些消费者侧的 AI 助手，理论上能直接接到你的店铺，不再需要做复杂的 SEO 和 SEM
- 长期：你需要重新思考"商品页面"还要不要花那么大成本——如果一半的下单是 Agent 触发的，前端的视觉设计、交互优化的优先级会下降，**商品数据的结构化质量**反而成了关键

至于具体怎么准备，建议很务实：先把 PIM（产品信息管理）那一层弄干净。Agent 通过 MCP 拉商品的时候，它看的是字段化的属性、规格、库存、价格，不是页面上那张漂亮的产品大图。如果你的商品数据现在还散在各种 Excel 和老系统里，**不管 MCP 上不上线都该先收拾**。

## 再说一句不那么好听的

这个 Storefront MCP server 现在还是 planned 状态。从 SAP 的产品历史看，"planned for Q2 2026"翻译过来通常意味着"Q2 末某些客户能拿到、Q3 才正式 GA、Q4 才有官方文档"。

所以这个东西的真正意义不在"它什么时候能用"，而在"SAP 到底有没有想明白"。从这次发布的动作判断——同时推 MCP 和 A2A、同时收紧后台 API 又开放前台目录——SAP 至少已经从概念上把 agentic commerce 这件事想清楚了。

想清楚和做出来之间还有距离。但比起去年那种"Joule 是个聊天框"的状态，这步棋的精度高了一个档。

所以那句"SAP 不在牌桌上"的判断，得改了。它没坐主桌，但它在偏厅悄悄摆了张椅子。能不能赢这局，要看 Q2 落地之后开发者们买不买账。
