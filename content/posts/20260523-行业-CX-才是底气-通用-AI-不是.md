"AI 是不是要把软件公司吃掉？"

这个问题 Balaji Balasubramanian 几乎每天都被问到。他是 SAP 客户体验和消费行业的总裁兼首席产品官。他的回答不是反驳，是把战场往后挪了一步——

**真正吃掉软件公司的不是 AI，是把 AI 套在垃圾数据上的那一波幻觉。**

这个观点放在最近这场访谈里，比 Sapphire 上 200 个 Agent 摆台子的口号要硬得多。Diginomica 的 Jon Reed 在 NRF 2026 之后追着他做了一次专访，主题是零售 CX，但讲的逻辑其实适用于所有行业。

## 一句话先抛出来

通用 AI 跑不动企业 CX，行业 CX 才能跑通 AI。

听起来像是产品总裁的标准卖货话术。但 Balaji 给的论据其实很朴素——AI 想要给力，需要上下文；上下文从数据来；数据要从你做了几十年的业务流程里长出来。

如果客户问 AI 客服"我的订单到哪了"，AI 答不上来，不是 LLM 不够大，是它根本没接到订单系统、库存系统、配送系统。

把这事讲清楚的不是模型公司，是做了五十多年业务系统的那批人。

## 体验和运营，是同一枚硬币的两面

Balaji 在访谈里反复强调一句话——零售商必须同时拿到"体验"和"运营效率"，不能偏。

> 如果你过度优化效率，体验就会崩。
> 如果你只押体验，成本会失控。
> 这两边是同一枚硬币的两面。

这话听起来像废话，但很多客户做选型的时候确实只看一面。

我看到的项目里，有些客户上 SAP Engagement Cloud (Emarsys) 只盯着邮件打开率，不管订单能不能履约；有些客户上 S/4HANA 把后台跑得飞起，但前端商城的客户体验还停留在 2018 年。两条线各跑各的，AI 进来也只是在瞎子身上又装一只眼睛。

## 那 SAP 真正在卖什么

Balaji 在访谈里点了三件 NRF 上发的东西，这三件其实拼出了一张完整的图。

**Retail Intelligence**——一个 AI 原生的零售应用。它不是给某个环节装个助手，而是把规划、预测、补货、订单调度全部放在一张企业级数据上做。这张图不只是 CX 的图，是 CX 焊在 ERP 上的图。

**S/4HANA 公有云里嵌入的零售能力**——把品类规划、促销、商品陈列、库存、采购、配送全做成原生模块。AI 用在哪？用在让运营那一面更高效。这一块不属于 CX 应用层，但它决定了 CX 能不能讲清"我有货吗"这句话。

**Agentic Commerce + MCP Server**——这是 SAP Commerce Cloud 这条线最近最值得看的一步。把商品、价格、库存信息开放成 MCP 接口，让 ChatGPT、Gemini 这些 LLM 渠道能直接发现你的商品。客户在 ChatGPT 里搜咖啡机，发现你家的，可以一路引流到你的线上店或者线下店，甚至在对话里完成购买。

这件事的意义不在功能本身，在于"商品发现"这个动作的入口正在迁移。官网、App、搜索引擎排名都不再是发现层的全部。Google 和 OpenAI/Stripe 已经发了 agentic commerce 协议，消费者预期已经在变。零售商要么进局，要么被绕过去。

## Experiential Loyalty——忠诚度不是积分

访谈里有句话挺值得划下来——

> 忠诚度不再是积分和会员等级。
> 是每一步都做得对、信息准确、用户对你产生了 affinity。

SAP 把这个叫 experiential loyalty。它和传统忠诚度计划的差别，类比一下：传统忠诚度像办公室门禁卡，每来一次记一笔；experiential loyalty 像是一个老熟人，每次见面都记得你上次说了什么。

这背后真正的产品是 SAP Customer Loyalty Management（CLM）——2026 年单独立项的独立产品。它把积分引擎从 SAP Engagement Cloud (Emarsys) 拆出来，做成一个能给所有渠道调用的能力包。SAP 把这一步拎出来做独立产品，不是为了多卖一个模块，而是因为忠诚度逻辑越来越要跟订单、库存、客服、营销同时调度——只属于营销那条线已经装不下了。

## 一个 4000 家门店的欧洲零售商怎么落地

访谈结束后 Balaji 又补了一段细节：欧洲一家超过 4000 家门店的零售商，十年前就把店员标配的工作设备从 PDA 换成了智能手机，所有店内流程逐步数字化。

最近这家客户上了一套**自主货架扫描机器人**——夜间作业，靠摄像头、传感器和图像识别，给货架建一个"数字孪生"。第二天店员一上班，哪些货架缺货、哪些 SKU 摆错了，全在手机上。

这套东西的关键不是机器人本身，是机器人扫出来的数据要回到 SAP Cloud ERP for Retail，再和电商的库存、营销的活动、客服的工单串起来。Click-and-collect 之所以能跑通，不是因为多了一个"线上下单门店自提"的按钮，是因为这家门店的库存可见性、员工工作流、客户体验三件事在一个底盘上。

## 员工体验，是被低估的那块

Jon Reed 在文章里抛了一个挺刁钻的问题——为什么很多厂商不谈员工体验？一个不开心的店员，是再花哨的技术栈都救不回来的最弱一环。

Balaji 的回答说明 SAP 在这件事上确实在动脑子。原话是：

> 我们和客户互动，也和供应商、分销商、合作伙伴、员工互动。
> 我们想做的，是把面向营销的客户体验，做成一个更广义的 engagement 层。

把客户和员工的数据放在同一张表上做 AI——能做这件事的厂商不多。SAP 同时拥有 SuccessFactors 和客户体验这两块资产，是它在这条赛道上为数不多的差异化。但能不能真做出来，这条线还得继续看。

## 对中国出海企业意味着什么

中国出海品牌做欧洲、美国、东南亚市场扩张时，在选型上经常会面临一个判断——是用本地的 SaaS 拼一拼快速上线，还是上一个能跨地区统一的平台。

Balaji 这次访谈里讲的逻辑，其实给了一个判断角度：如果你的业务模型里，订单履约、库存可见、价格策略、客户标签需要跨多个国家协同，那行业级的体验加运营这条路是绕不开的。AI 客服 demo 看着炫，但客户问"我的订单到哪了"，答不上来就是一切归零。

跨境电商做得久的中国卖家应该都能体会——欧美买家对"订单状态精确到几点几分"的要求，比国内电商苛刻得多。这就是为什么 SAP 一直把订单可见性当成核心能力来卖。最近独立出来的 SAP Order Management Services（OMS）走的就是这条路——4 个 PBC 模块，按能力包独立计费，跨境场景能挑着用。

## 一个具体的行动建议

如果你正在评估 SAP 客户体验产品组合或者已经在用，回去做一件事——把公司里"体验"和"运营"两条线的负责人拉到同一个会议室，让他们各自说一遍：客户问"我的订单到哪了"，从下单那一刻起，订单状态在哪几个系统流转、哪些字段是同步更新的、哪些是 T+1。

如果他们说不清楚，AI Agent 也不可能说清楚。

**行业 CX 的底气，从这道题开始。**
